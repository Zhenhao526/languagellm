# 三人消息实验：源码与运行说明

本目录采用已有 Qwen 虚拟环境中的 Python／NumPy，**不加载 Qwen、MLX、Torch 或任何预训练权重**。正式训练由根任务在方案、源码、数值审计和离线测试核对后启动；本文件不是已经执行的记录。

## 命令与一次性执行

从项目根目录运行：

```bash
qwen_collect_pilot/.venv/bin/python -m unittest discover -s research_program/triadic_message_study/tests -v
qwen_collect_pilot/.venv/bin/python -m research_program.triadic_message_study.runner prepare --out research_program/triadic_message_study/results/messages_001
qwen_collect_pilot/.venv/bin/python -m research_program.triadic_message_study.runner verify --out research_program/triadic_message_study/results/messages_001
qwen_collect_pilot/.venv/bin/python -m research_program.triadic_message_study.runner execute --out research_program/triadic_message_study/results/messages_001
```

`prepare`仅构造确定的任务划分、动作表、配置及源码快照，不创建网络、奖励数组或 worker。`verify`核对当前与快照字节、准备内容及 Python／NumPy 版本。`execute`拒绝已有 execution 目录，不能续跑或覆盖部分失败。低成绩不触发重试。所有子进程都再次核冻结内容，结束前父、子进程也再次核对。

四个进程采用 `multiprocessing` 的 spawn 模式，每个种子内部串行运行 FI_silent、FI_live、PI_silent、PI_live。每个进程在导入 NumPy 前强制四个 BLAS／OpenMP 环境变量为1。进程只共享只读源码与准备文件，各自建立 FI／PI 数组和奖励表；父进程按固定种子／条件顺序汇总并核查数组哈希、初值、6000 个世界批次和消息 U 哈希。发现任一进程异常，父进程只终止自己持有的本次 worker，并保留失败记录；不查找或停止其他任务进程。

## 核心接口与数值约定

`make_networks(seed)` 返回长度9的列表，顺序为 A 的 sender1、sender2、action，随后 B、C。每个模块参数为 `W1/b1/W2/b2/W3/b3`，无参数或隐状态共享。每主体47313参数，三人共141939参数。`base.actor_forward/backward`、Adam、原观察编码和物理结算复用冻结基线；稳定 logJ 和行动梯度复用冻结的目标对照模块。

`rollout(networks, observations, live, uniforms=None)`：输入观察为 `[B,3,54]`；消息 U 为 `[B,2,3,4]`，省略时逐位置贪心。两窗全部产生后再构造下一阶段输入。返回消息 `[B,2,3,4]`、发送概率 `[B,2,3,4,8]`、行动 logits `[B,3,17]` 及研究者可见的计算缓存。缓存没有输入其他主体。

`routed_window(messages, live)` 的输出为 `[B,viewer,99]`。每位听者先得到 A／B／C 顺序的96个 onehot 数值，再得到3个可见位，**可见位不是交错插在每个32维内容后**。每个发送者的4位置按原顺序展开。silent仅保留本人onehot及可见位，跨人内容及可见位全零。符号0仍是可见符号，不是缺失值。

`training_gradients`一次使用同状态两条完整独立轨迹，返回九套梯度及日志量，不更新参数。两条轨迹按 trajectory-major 拼成2B输入。发送端最小化停止梯度后的负 score surrogate：`−Σ_r,b advantage[r,b] logq[r,b]/B`，其中两个 advantage 为 `(F1−F2)/2` 及其相反数，logq累加全部24符号。该 surrogate 的数值不是任务目标或学习进展指标；其梯度才是估计对象。两窗均使用最终F，第一窗因此包含经第二窗产生的未来作用。receiver梯度除2B，不额外除发送者或符号数；三人均值熵的除3已在冻结熵函数内。

世界流为 `SeedSequence([seed,200])`；初始化为 `[seed,agent,module,100]`；12个消息流为 `[seed,agent,trajectory,window,300]`。condition不进入流。每更新即使silent也完整抽取 `[2,B,2,3,4]` 的U，各主体、轨迹和窗独立，四条件U逐值匹配。U不作为网络特征，训练行动不另抽样，因为本轮使用条件于消息的精确行动期望。

## 保存内容与离线测量

每个 worker 在 `execution/worker_seed_N/` 保存启动、输入数组哈希和完成／失败记录。每条件在 `execution/seed_N_CONDITION/` 保存：

- `training.jsonl`：世界批次、打包状态、外生U和已采样消息的SHA；两轨迹平均 J／logJ／F、最小logJ、浮点J零值计数、行动熵、sender advantage和surrogate、总梯度范数及裁剪比例。完整连续消息样本不逐更新存成巨量JSON，可用保存的RNG流和批次重建外生U，但重建历史策略仍需要重放优化。
- 六个 `checkpoint_XXXX.npz`：九套参数、九套Adam状态、世界及12个消息RNG状态。参数键形如 `agent0_sender1_W1`；`load_networks(path)`仅读取并核对九套参数，不做前向。
- 每检查点四份 `monitor_XXXX_PARTITION.npz`，以及四份 `final_PARTITION.npz`：实际state_indices／states、两窗真实生成消息、实际动作及行动概率、原R、执行和需求满足。silent中保存的他人消息是研究者记录，不能解释为已投递给该主体。
- `result.json`：全四格R0／R0.5／R1、全部失败、伙伴对、动作种类及监测。父进程仅在16个条件运行全完成后写正式 `execution/results.json`。

NPZ中 `conditional_exact_*` 和对应JSON均值，是给定当前贪心消息后对三人行动分布的精确统计，不是对整个随机发信协议的积分。每次正式评价均为贪心消息再贪心行动，精确并列取最小原索引。消息种类、重复或可读形状不能直接作为语义证据。研究者私人事实配对和末点消息干预由独立脚本负责，不输入主训练器。

总预算96000更新、24576000状态抽样、49152000条完整通信轨迹；每条24个分类抽样，共1179648000个符号抽样及同数的24项原生奖励加权贡献。四个 worker 实际重复预计算13768704个奖励项。预计内存约数GB、压缩记录约1–2GB；单进程静态乘加估算约为上一8次目标对照的21.5倍，约30分钟仅作粗略量级，四进程实际墙钟时间需记录，不以成绩pilot估计。

离线测试只检查信息／时序／数值接口与准备边界。随机scratch网络测试使用非正式种子和人工数组，无环境任务成绩、优化器更新或正式训练；单个手工全等待政策用于验证失败保存与原生结算。独立数学审查另以小状态空间的全轨迹／轨迹对枚举及有限差分核查发送估计，不依赖训练表现。
