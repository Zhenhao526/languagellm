# 搭档组合留出确认：结果与下一步

## 这轮要检验什么

前几轮已经看到：在固定搭档和固定行动接口中，实时通信可以提高合作行为，但整包编码重命名会破坏响应，且未见对象×属性组合没有稳定地获得额外 Q 响应。这里把“搭档关系本身”作为留出轴：训练时完全排除一个 AB、AC 或 BC 目标搭档组合，留出时再要求这两名主体合作。

训练和留出中的每个主体仍然出现全部对象、属性和目的地个人需求；因此这轮改变的是三人社会关系的组合，而不是某个对象或属性值从未出现。若通信和收益压力能够让主体抽象出“谁与谁需要协作”的关系结构，未见搭档上的行为应该高于无通信和部分收益基线。若结果只在训练见过的搭档上成立，则固定关系策略是一个明确的生态边界。

## 预先冻结的设计

- 16 个新初始化：66101–66116。按 `(seed−66101) mod 3` 轮换留出 AB、AC、BC，数量为 6/5/5。
- 每个种子运行 `partial/all_or_nothing × strict/reciprocal × live/silent` 八格，共 128 次训练；每次 6,000 次更新，batch 256，检查点为 0、100、500、1500、3000、6000。
- 每个世界有三人的私人对象、属性、搭档和目的地需求，以及四个公共材料位置；动作菜单为 17 个。本轮不加入加工前置步骤和道路事件。
- 训练保留另外两个搭档关系，各 1,792 个需求；被留出关系为 1,792 个需求。训练使用 18 个布局；末点另测 6 个新布局上的未见搭档和已见搭档控制。
- 主量是未见搭档两名目标主体的精确目标行动率，而不是两人同时成功的 AND：

  ```text
  [(all_or_nothing live − silent) − (partial live − silent)]
  ```

  每个种子和规则先扣除第 0 步，再按真实检查点间距做梯形积分并除以 6,000，随后等权平均 strict/reciprocal 和 16 个种子。团队 Q（两端都正确且物理执行）是次量；物理执行率和第三名主体的 wait 行动单独记录。

完整冻结方案见[实验方案](plan.md)、[冻结记录](results/confirm_001/freeze.json)和[静态准备记录](results/confirm_001/prepared.json)。冻结的计划 SHA 为 `4eaf04a5c4796e7c2281c1b59c2f543d0b83c95482c7d4d7de1ad524ae1495c7`，准备记录 SHA 为 `e331b3f4992b19ce4c988690133c1b94707b4163b052325e9a56e557d2a37d3f`。

## 执行、恢复与审计

128 个条件都完成了训练、6 个检查点和训练日志，共 768 个检查点。最终汇总器随后因错误地要求不同种子共享同一 worker 数组，在最后一步抛出 `ValueError('Worker arrays differ')`；这是由每个种子有意轮换留出搭档造成的分区差异，不是模型或 checkpoint 损坏。原始失败保留在[执行失败记录](results/confirm_001/execution/failure.json)。没有重训，也没有修改训练参数。

第一次 JSON 汇总还暴露了后处理器读取轨迹字段的兼容性错误，保留在空的历史目录 `aggregation_001/`。修正 `metrics.py` 后，只从已有 `result.json` 读取 `row['target_trajectory']` 完成[JSON-only 汇总](results/confirm_001/aggregation_002/results.json)；[汇总收据](results/confirm_001/aggregation_002/receipt.json)记录了这一项 post-run source edit。该修改只影响读取和聚合，不改变训练、checkpoint、参数、奖励或预注册主量。

独立审计从 checkpoint 重放了 768 个检查点、148,635,648 个紧凑评价世界和 1,337,720,832 次模型前向，优化器更新为 0，轨迹和搭档轮换均通过，最大绝对误差为 0。[审计验证](results/confirm_001/audit_001/verification.json)和[审计收据](results/confirm_001/audit_001/receipt.json)可复核这些数字。聚合本身没有新增模型调用或优化更新。

## 终点诊断：未见搭档与已见搭档分开

下表是 16 个种子平均的目标主体精确行动率（silent → live）。`heldout_pair` 使用训练布局，`heldout_pair_new_layout` 使用 6 个全新布局，`seen_control_new_layout` 是同一新布局上的已见搭档控制。

| 分区 | partial strict | partial reciprocal | all-or-nothing strict | all-or-nothing reciprocal |
|---|---:|---:|---:|---:|
| 未见搭档，训练布局 | 15.7821 → 23.5202% | 9.2708 → 2.5587% | 0.0000 → 0.0000% | 0.0000 → 0.0000% |
| 未见搭档，新布局 | 14.2142 → 21.2915% | 8.5975 → 3.0370% | 0.0000 → 0.0000% | 0.0000 → 0.0000% |
| 已见搭档，新布局 | 11.4679 → 21.3368% | 21.2227 → 26.4637% | 18.5392 → 87.3584% | 48.0413 → 96.7227% |

最清楚的边界在全有或全无收益：已见搭档可以在通信下大幅协调，而未见搭档两名主体的目标行动率在训练布局和新布局都为 0。partial strict 的未见搭档有一定行为响应，但 partial reciprocal 的 live 值反而下降；这使得总体主量接近零，而不是稳定的正泛化。

按未见搭档的训练布局分层，partial strict 的 silent → live 为 AB 15.2035 → 18.5100%、AC 25.1969 → 41.8721%、BC 7.0616 → 11.1806%；partial reciprocal 为 AB 8.0346 → 2.1572%、AC 8.4834 → 3.3699%、BC 11.5415 → 2.2294%。两种 all-or-nothing 规则的四个搭档分层终点都为 0 → 0%。这些数字是诊断，不是额外确认性检验。

## 证据能说明什么，不能说明什么

这轮没有得到“通信和收益压力使未见搭档关系产生稳定行为泛化”的确认性证据。已见搭档新布局的高分说明学习器和任务并非完全不能执行两人协调；未见搭档的全有或全无结果则显示，训练中出现的固定关系很可能被当作局部策略、角色绑定或查表入口，而没有抽象成可迁移的社会关系规则。

这不是词义或语言形成的负结果。消息通道、符号包和动作接口在这轮已经存在，实验测量的是既定通信下的行为泛化；没有检验公共词典、可组合形式、意义稳定性、代际传承或新主体学习。`Q` 也只是两个端点同时正确的任务指标，不能当作语言程度分数。

还有三个必须保留的混淆：

1. `all_or_nothing` 只在训练目标中把半成功映射为 0；它可能造成稀疏奖励和信用分配困难，使未见搭档更难出现第一步协调。
2. 当前动作菜单和 wait 机制仍可能让主体通过固定角色或单一行动捷径获得收益；物理执行率的强负交互说明动作接口本身参与了结果。
3. 训练中每个搭档关系出现的频率和三人角色的对称性虽已配平到本轮方案，但不同 AB/AC/BC 留出层的方差仍然较大，不能把单个种子解释成机制。

## 下一步实验决定

下一批不再增加训练步数，也不把未见搭档的零结果改写成语言证据。优先改造能区分“关系抽象”与“固定搭档局部最优”的生态：

1. **随机重配搭档。** 在训练中让同一主体与多个主体轮换配对，并保持每个对象、属性、目的地和搭档边际分布；测试时留出一个新配对，另设已见配对和同布局／新布局控制。
2. **多合法行动。** 对每个世界提供至少两个可完成的安全行动和显式中性行动，避免未见搭档必须先猜中唯一动作才能产生学习信号；把个体目标行动、搭档联合行动和团队收益分开预注册。
3. **方向可识别的通信干预。** 对单一发送者做消息替换、遮蔽和接收者交换，测目标接收者的动作变化；保留 silent、随机符号重编码和包内结构控制，避免把整包触发误报为成分意义。
4. **形成而非只看终点。** 在新的独立种子上保留 0/100/500/1500/3000/6000 检查点，预先规定目标主体行动率和 Q 两条结果线；若出现可重复的跨搭档响应，再测新主体或下一代是否能从消息中恢复同一约定。

当前最有价值的结论是一个可反驳的边界：**在本任务和学习器中，通信能改善已见关系的协调，却没有自动产生对未见社会关系的可迁移约定。** 要把它推进到语言起源问题，下一轮必须先证明跨主体关系、方向和可替代行动上的功能结构，再讨论消息形式是否获得稳定的组合意义。
