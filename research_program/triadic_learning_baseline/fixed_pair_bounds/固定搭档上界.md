# 固定搭档对的任务静态上界

本次只读取当前 `runner.make_prepared()` 返回的固定四格及源代码，独立枚举需求谓词；没有读取训练结果、策略权重或未来成绩，没有训练，也没有给 actor 添加任何标签或动作。这里的上界允许指定两人根据完整当前信息，完美选择物资位置和目的地，并互相匹配；第三人始终等待。它比一支实际学得的固定搭档政策更强。

**任一固定单对 AB、AC 或 BC 的满分上界，在需求训练域为 79.9218%，在需求留出域为 83.4061%。** 三对数值完全相同：固定划分保留每个需求多重集的全部主体排列，因而对主体置换对称。布局和私有观察地点分配不改变完整信息下的存在性判断。

每行同时适用于 AB、AC、BC；逐对的兼容／不兼容需求清单与精确分数保存在 `enumeration_001/bounds.json`。这是完整有限支持的精确计数，不是抽样估计，不需要置信区间。143424 个世界也不是143424次独立训练重复。

## 推导及核查

每个需求是四种谓词 wood、fiber、short、long 之一，与允许目的地 L、R、L/R 之一的组合，共12种。每种需求接受2种材料、至少1个目的地。独立枚举每需求的可接受 `(material,destination)` 集，两个集合交集非空即该对兼容。

四种材料在每个世界各有一件，完整信息者可定位任意材料；全部目的地动作均保留。若兼容，两人可以同时满足，最优 R=1；若不兼容，不能同时满足，但总可选择满足其中一人的物资及目的地，最优 R=0.5。因此兼容比例为 c 时，固定单对的满分上界为 c，原奖励最优均值为 `(1+c)/2`。接近0.9的原奖励本身并不排除固定单对。

脚本从全部1728张有序需求表独立筛得996张至少有两条兼容边的支持，按固定种子重新生成需求多重集与布局划分，与 `make_prepared()` 的每格需求、布局、公开分配顺序逐项一致。另以96个需求×材料×目的地案例核对原环境谓词，但上界计数不调用原环境的兼容函数。需求训练域中462表有恰好2对兼容、305表有3对；需求留出域分别为114和115表。枚举前后源哈希一致，清单见 `enumeration_001/manifest.json`。

## 能由超过上界推出什么

“每场至少两对可行”不等于“同一对在所有场景都可行”。例如一人需木材到 L，另一人需纤维到 L，第三人需短材料到 L：前两人的固定配对无法同时满足，第三人分别与其中任一人可以满分。四格中每个固定单对都存在相应的不兼容子集。

在完整终点格中，若一支社会的真实满分率超过相应最佳固定单对上界，它不可能始终仅执行同一搭档对。对任何预先选定的默认对，达到99%满分至少需要在总世界的19.0782%（需求训练域）或15.5939%（需求留出域）中，由其他对取得满分；有限世界中相应计数须向上取整。这是必要下界，不表示主体有显式的伙伴推理或词汇。与需求无关地随机混合三个固定对，在期望上也不能超过它们的相同单对上界。

**但不需要三种配对都出现。** 支持图总共只有3条可能边，每表至少2条可行，因此任意预先选定的两条边都必与可行边集相交。AB+AC、AB+BC、AC+BC 三种受限组合，在完整信息完美选择的条件下，逐格均可达到100%满分和 R=1。它们分别允许 A、B、C 永远参加运输，只在另外两人中选择搭档。

因此超过单对上界支持“实际使用了至少两种配对”，并不支持三对全面覆盖、所有主体轮流等待、固定中心角色消失或伙伴表达已经形成。自主形成固定中心分工可以是后续需要描述的行为结果；不能仅为让三种关系都出现而修改当前任务。这些参照全部是任务结构与行动上界，**不构成语言证据**。

运行方式：在项目根目录执行 `qwen_collect_pilot/.venv/bin/python -m research_program.triadic_learning_baseline.fixed_pair_bounds.enumerate_bounds`。脚本拒绝覆盖已有 `enumeration_001`；不会调用训练或模型推断。结果仅存在本新目录，原环境与计划未修改。
