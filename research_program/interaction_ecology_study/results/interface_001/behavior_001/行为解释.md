# interface_001：公开方案与实际行动

这是完成全部288次调用后所做的描述性行为分析。分析程序不导入原环境结算函数，按规则独立重算了全部24场物理匹配、需求满足、反馈和收益；同时核对72项正式选择与完整17项私人菜单、36个动作配对和12场收益转移。24场结算与原始日志逐字段一致。没有读取私有分析，没有调用模型，也没有修改原实验文件。

## 实际发生了什么

两臂均为4/12场满分，12个配对场次的收益完全相同：8场保持0，4场保持1。35/36个语义动作相同。按生成重复看，401组0/4、402组2/4、403组2/4；按四个场景看，依次为1/3、0/3、1/3、2/3。两种输出接口的这些计数完全一致。这里是4个抽样世界、各做3次生成重复，不能当成12个独立世界。

| 互斥结算类别 | 编号臂 | 动作原文臂 | 实际含义 |
| --- | ---: | ---: | --- |
| 仅一人提交运输 | 7 | 7 | 没有实际搬运；需要配对的另一人未参与 |
| 三人提交运输 | 1 | 1 | 触发最多两人活跃的容量规则，全部不执行 |
| 两人提交但未匹配 | 0 | 0 | 本批没有此类完整场次 |
| 两人实际匹配但需求不全满足 | 0 | 0 | 本批没有此类实际执行 |
| 两人实际匹配且需求均满足 | 4 | 4 | 各满足两人，收益1 |
| 全体等待 | 0 | 0 | 本批没有此类场次 |

每臂共有18个运输提议、18个等待动作；仅8个运输动作实际执行，并满足8个人的需求。不能把18次提议写成18次成功采集或交付。7场单人提议中均是A运输、B和C等待；其中6场A指定B，另1场 `g401_e2` 指定C。这是当前记录的角色分布，不能据此宣称B有跨场景、跨模型的一般性能力缺陷。

`行为核对.md` 中伙伴、位置、目的地的未匹配计数只统计“恰有两人活跃”的场次，所以三项均为0。它不表示超载场次中的三人提议彼此匹配。该场的各对维度单独列在下面和 `behavior_findings.json` 中，不与互斥结算类别相加。

## 唯一动作变化为什么仍失败

`g402_e2` 的状态与两臂动作如下。C需要纤维、目的地L；S1实际是短木材。所有信息在完整信息观察中都已提供。

| 主体 | 编号臂动作 | 动作原文臂动作 |
| --- | --- | --- |
| A | 与B，S1→R | 与B，S1→R |
| B | 与C，S0→L | 与C，S0→L |
| C | 与B，S1→R；私人菜单2 | 与A，S1→R；私人菜单15 |

唯一改变是C的搭档B→A；位置S1和目的地R未变。两臂都有三人运输，因而都触发超载，收益0。额外的提议结构也没有变成可执行的完整配对：

| 臂／候选两人 | 互选对方 | 同一物资位置 | 同一目的地 |
| --- | --- | --- | --- |
| 编号／AB | 否 | 否 | 否 |
| 编号／AC | 否 | 是 | 是 |
| 编号／BC | 是 | 否 | 否 |
| 原文／AB | 否 | 否 | 否 |
| 原文／AC | 否 | 是 | 是 |
| 原文／BC | 否 | 否 | 否 |

因此，不能把C从B改选A写成“修复了配对、只是超载掩盖收益”。它仍未与A互选：A选择的是B。编号臂原有的BC互选也同时存在位置和目的地冲突。此外，两臂C的S1/R提议即使能执行，也既不满足其纤维需求，也不满足其L目的地需求。这里将容量、匹配维度和需求兼容性分开描述，没有把它们相加成多个独立失败场次。

该场最后一窗，A和B都明确提出“AB运S1至R，C等待”；C明确提出“BC运S0至L，A等待”。这是两个不同的、各自可得1分的公开方案。实际A与自己最后一窗的提议一致；B正式动作改为BC方案；C在两臂中都没有采用自己最后一窗所说的S0/L。文字和行动的差异可直接核对，但不能据此推断C的私有意图，也不能把B的动作归因为某一条特定旧消息。

## 72条公开广播能说明什么

逐条判读已保存在 `../public_text_codings.json`，每条均绑定原始文本、原文引句、分类和说明。采用的是单个agent的明确文本编码，不是人工标注，也没有独立双人一致性。该分析是在已知本批行为结果之后进行的，属于事后描述。

52条消息明确给出三人的完整方案，9条只能确定发言者本人的动作，11条无法唯一补全为一个动作方案。完整方案要求同一条消息明确搭档、位置、目的地和第三人的等待或不参与；仅提出一对搭档时，不从容量规则替发言者填入第三人的动作。完整方案也可能错误：52条中46条若按原文执行可得1分，6条只能得0.5。这是52条消息的计数，包含重复提议，不能当成52次独立规划测试。

两处B发出的“我 C 等待/保持等待”保留为身份指称有歧义；“沉默。”是实际发送的非空消息，不当成无消息或等待动作；包含两个位置或条件备选的文本也不替发言者选一个。`g402_e4` 的“放弃C需求”没有自动被补成C等待。个别请求确认虽然足以确定提议对象，仍只编码其方案内容，不算对方已接受。

最后一窗的严格文本分类是：3场三人各自明确写出同一个完整方案，5场存在不同的明确完整方案，4场只有一两人明确写出完整方案。这些类别描述文字，不能替代对共同接受、承诺或实际协调的测量。同窗消息在全部收齐后才向三人公开；表格中并列的第二窗提议，不表示说话者已经看到并接受了同窗别人的提议。

三个最后一窗明确方案相同的场次（用词并非逐字相同）是 `g401_e1`、`g401_e3`、`g403_e2`。其明确方案均可满分，但两臂正式动作都是A运输、B等待、C等待，实际收益0。这给出一个直接的行为证据：本批中“能写出一致的可行方案”并不保证动作落实。它没有证明B内部已经理解、接受或形成稳定承诺，也没有定位失配究竟发生在哪个内部环节。

相反，成功场次也可出现最后一窗提议差异。例如 `g402_e1` 的A/B提议AB运S3→R，C提议AC运S3→R，实际却是AB运输、C等待，得1分；`g403_e3` 中B最后提议S0，而A/C写S2，实际三人执行了AB运S2、C等待。不能把三人最后一窗的明确方案一致当作本任务成功的必要条件。这些例子也不能证明冲突促进成功：没有随机操纵冲突，且只有4个世界。

## 对当前研究路线的限制

本轮改变了完整输出接口，包含选择串的token化、长度和受限贪心分叉方式；两臂共用同样的动作前输入、广播和精确重现的私有分析。结果不支持“在当前完整能力批次中，只要把编号改成动作原文就能消除主要失败”这一候选解释。它不能证明编号映射在所有设置中均无影响，也不能从35/36动作相同识别唯一内部原因。

本批使用现成自然语言交流，尚未研究新符号约定如何形成。新接口未达到12/12的可行性门槛；旧门槛也没有因本分析而改变，符号阶段没有解锁。本轮按既定停止规则结束，不追加同类接口修补或模型调用。面向约定形成的后续主张仍需要一个独立通过能力检查的完整配置，不能用这些自然语言提议或偶发成功替代。

完整数值、全部36对动作、全部72条广播与方案到动作的对应关系见 `behavior.json` 和 `行为核对.md`。输入及分析源码SHA在JSON中保存。全288条模型输入、token和冻结来源核查由另一个独立执行审计负责，本文件不冒充该项审计。
