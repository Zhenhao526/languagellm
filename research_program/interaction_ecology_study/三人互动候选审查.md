# 三人互动：修复机会候选与能力接口修订

2026-09-15。设计审查，未冻结、未执行。只读既有环境、CAP／EXEC输入与结果；没有模型调用或旧源码改动。以下不把已失败的能力门槛改成通过，也不把外部计划执行当作自主协商。

**保留一个研究候选：在共同动作前，中途收到的伙伴回应能否再被回应，是否影响约定的形成与修复。当前先不运行它。** CAP有回应窗口仍只有4/12场满分，外部共同计划也只到10/12；现配置中增加互动的效应会混入动作接口的不稳定。一个值得完整检查、但不保证有效的修订，是保留全部17项动作，把正式选择由私人编号改为完整动作原文；在新能力批次中配对核验，不给正确方案、不筛掉合法坏动作。若这一修订仍不可靠，停止这条互动解释，不靠继续增加请求或提示追成正结果。

## 1. 现有证据限定了能问的问题

用户关心三个独立主体在对象、属性、搭档与目的地约束下形成约定，已要求取消加工和道路事件。v3保留多步搬运与交付、种类／长短／干湿、私有句柄及搭档协调；两场完整信息检查是0/2件和3/3件，未全部过关。后来的 triadic_task 是另一个一步诊断环境：四物资为短／长木材与短／长纤维，四位置、两目的地；保留对象、属性、搭档和目的地，但没有干湿、多步搬运或交付规划，不能称作已验证全部v3能力。

triadic_task 的D1规则要求恰好两人运输、互选、同物资位置、同目的地，第三人等待；每人17项完整合法动作。合法不等于能执行或得分：选择不兼容物资、错搭档、错目的地、三人同时运输均可正式提交。这里不更改这些动作与原结算，也不增加工具、加工或道路事件。[环境接口](../triadic_task/environment.py)

[CAP](../triadic_task/results/20260915_CAP_01/结果与下一步.md)的两窗自然语言已经允许提出方案和回应。群体303场景2，第二窗三人都提出A/C共同从S0送长纤维至R、B等待，最终C改选S3短木材。群体303场景3中，A/C的方案本可成功，但B也运输导致超载。反过来，群体302场景4中广播称等待／没有方案，正式动作却成功配对。故“提议一致”“自述接受”“动作一致”“物理成功”是不同观察。

[EXEC](../triadic_task/results/20260915_EXEC_01/结果与下一步.md)给出完整正确方案后，34/36动作吻合，仍有两例合法语义错误：302场景2的B选错搭档；303场景1的B等待而没有参与新计划。它们不能仅凭私有分析解释成编号翻译错误，但足以说明当前失败不能全部归因于没有澄清或承诺。共同计划干预同时提供答案、执行指令并降低旧提议的优先级，不能用10/12替代CAP的12/12门槛。

需求已知／隐藏在v0.5已经直接配对做过；固定／学习的发送接收顺序也是既有工作或另一候选。本文的互动候选不再把这些当新操纵。旧v2亦已有四窗即时／整段延迟通信，所以“允许回应”本身没有本地新颖性；下面只能算更有针对性的修复机会与过程检验。[需求时点核对](../probability_coverage_study/需求时点_既有实验核对.md)

## 2. 可保留的最小互动候选：只延后第二窗的伙伴消息

任务始终采用同一局部观察和D1共同动作规则，不同时加入需求可见性或行动独立性条件。两组均四个同步窗口，窗口内先收齐三人的输出再投递；物理动作只在全部通信结束后同时结算。没有预设“请求”“回答”“承诺”的固定字段或固定说话人，每窗也允许沉默。

| 事项 | 正常四窗 | 第二窗回应延后 |
| --- | --- | --- |
| 第1窗消息 | 窗末公开 | 相同 |
| 第2窗消息 | 窗末公开，可影响第3、4窗输出 | 自己的输出仍可见；伙伴此窗文本到第4窗全部发完后、物理动作前才公开 |
| 第3、4窗消息 | 各窗末公开 | 相同；允许主体自行重述第二窗内容或采取其他策略 |
| 最终动作前 | 已获得本轮所有实际广播 | 同样已获得本轮所有实际广播，包括延后第二窗 |

这仅移去一个中途反馈机会，保留首次交换和其余窗口。第二窗未必真是回应，是否出现请求／澄清／承诺须由行为证据判断；不能把窗口号当作对话行为标签。后者仍可利用第1窗协调，也可在第3窗重述；若两组无差别，不能说所有互动均无作用。

符号设置沿用用户既有政策：字母表`@#%&*+=~`，单条最多32字符，每人每物理步合计64字符，顺序不改；自由变长、不规定词或句法。四窗和12个潜在发信槽位相同，三份原始私有经历隔离，不增加私人笔记；每次私有分析的token上限与正式输出规则相同，分析从不成为通信。每步两组均15个决定、按既有两阶段后端即30次调用。新批次若使用这一设置，需要新源码和输入审计；不修改旧协议模块。

### 能控制什么，不能声称控制什么

| 维度 | 固定或变化 | 解释边界 |
| --- | --- | --- |
| 世界事实与初始可见信息 | 同状态、局部材料、本人需求、观察分工配对；本轮不改变哪些需求公开 | 不是known／hidden需求对照 |
| 名义带宽 | 同字母表、32／64上限、4窗 | 自主消息长度和实际信息量可能不同；不能称“相同语义信息量” |
| 发信和计算机会 | 同发信槽位、同物理动作数、同私有推理上限 | 有效可回应链条变短是操纵本身；实际token数、耗时并不因此自动相同 |
| 收信内容 | 动作前收到本组全部实际文本 | 两组后续文本会因早先收信不同而变化，不能声称最终逐字相同。强迫重放相同文本会取消需要研究的适应 |
| 行动依赖 | 始终D1、全部17项合法动作、不改评分 | 不能将条件差解释成分工是否必要；共同容量仍在 |
| 物理规划 | 无新增道路、加工、移动或中途世界变化 | 互动历史的组织负担会改变，尚不能把效应唯一归为语用能力 |

必须按固定窗口投递，日志区分原发送窗与实际可见时点；模型不得从调用时长、额外空调用或研究者全局日志得到信息。不得公开私有动作草稿、物理正确答案或自动“已达成一致”灯。若把研究者解析的理解、正确搭档或正确提案反送主体，就增加了一个有语义的外部通信通道。

### 怎样才超过“多交流提高得分”

候选预测是：在同类任务上逐步积累的约定，使一人的当前符号回应稳定地改变另一人后续表达或动作；中途延后回应会阻碍这个链条，尤其在伙伴表述尚有分歧时。这里不预设必须形成两种词或某种语法。

最低证据应包括：完整的独立群体过程记录；在提前固定的观察点保存合法状态和三人私有历史；从同一快照只改变当前第二窗投递，重新生成后续两窗和三人动作；记录成功、失败、动作改变但收益不变和重复表述补偿。该分叉只测当前反馈机会，不能替代从头运行两种互动生态的形成比较。新表达在新对象属性组合、伙伴或目的地变更中能否被正确使用，还须另有未参与选择规则的测试；只在固定场景上整块编码仍足以完成任务。

若只见平均得分变化，却没有稳定的内容—回应—行动关系，应报告交互路由影响任务表现。若差异只来自更多文字、长私有思考或原本自然语言就不可靠的菜单操作，不可称发现约定形成机制。若请求或承诺只有模型自述，而接收者行为不随内容变化，也不算已经形成共同理解。U/C一类有限DINO码表测量不能直接套到未枚举全部LLM历史与消息的三人系统。

这个候选目前没有锁定种子数、经历长度、统计判据或新模型预算，**不能作为已经冻结可执行的正式矩阵**。它也未获外部先行工作的新颖性确认。

## 3. 当前更有根据的修订：正式选择完整动作原文

现有完整菜单本来就含每个编号对应的完整语义动作。修订只把正式输出语言从“输出本地编号”改为“输出所选那一项的动作原文”，例如“与C互选合作，从S0取物资并运送到R”。所有17项及其随机显示顺序完全保留，包括等待、错搭档、错物资、错目的地和会导致超载的选择。输出约束是17条字符串的完整集合；解析后映射回原动作字典，由原settle计分。

不提供推荐动作、共同方案、兼容伙伴名单或正确编号；不先由研究者／另一个模型从17项筛选；不把语义不成功的动作判为格式无效并重试。编号臂和原文臂都只有一次正式选择，失败原样保留。动作输出属于每人原有物理控制接口，绝不作为额外广播公开；它不是给符号通道提供词典。

这个修订免去最后一次把完整语义选择转换成不透明编号的要求，可能减少一类执行偏差。但受限生成的token路径也改变了，原文更长、利用预训练词汇先验更多；即使有效，也只能报告这个完整接口修订的操作效果，不能证明旧私有分析已经正确、形式化选择是唯一问题或模型已形成承诺。EXEC的两例也可能在原文接口下照样选择错搭档／等待，属于明确反证。

### 一个完整、预算明确的新能力批次

建议在看新场景之前冻结四个新IID语义场景的种子，从原996需求表支持抽样，不按是否容易协商重抽；各场仍由研究者枚举可解性，但见证不进提示。每场用三个生成重复，各有A/B/C独立上下文，共12次三人协商。这里仍只有四个语义场景，三个生成重复共享Qwen权重，不能称12个独立世界或三个独立训练模型。

每次从三人的空历史开始，先共同生成两窗真实自然语言广播，随后保存动作前快照。广播阶段不知道将采用哪种正式输出格式；中性规则说明只要求随后从完整菜单选动作，不提前宣告唯一编号格式。由同一快照分叉编号臂和原文臂：三人的观察、全部广播、完整菜单、私人分析提示和决定种子均相同，只有正式阶段的输出说明与词法约束不同。原样保留两阶段推断；同seed、同输入的私有分析应精确重现，否则停止解释配对效应，不用其内容当正确答案。

| 实际新增工作 | 调用数 |
| --- | ---: |
| 12次协商，各三人×两窗×两阶段；两臂共用此前缀 | 144 |
| 编号臂：12次×三人×两阶段 | 72 |
| 原文臂：同上 | 72 |
| 合计 | **288** |

每臂各自相当于216次调用的完整经历；共用已经发生的真实广播节省重复生成，不伪造或按胜负选择文本。两臂动作均不进入另一臂的提示，也不回写后续场景。每场空历史有意把能力检查与形成学习分开；它与旧CAP群内四场连续历史不同，所以新旧总成绩不能直接归因于动作格式，**可归因的比较只有同一新快照下的两种正式接口**。

两臂同私有分析上限、广播上限、温度、决定次数及种子。正式输出共同上限在准备时根据17条候选在冻结tokenizer中的最大长度确定，不能按结果延长。原文实际通常输出更多token；报告真实token、耗时和截断，不把调用数匹配写成完全相同计算量。两种约束均需词法完整性、全部17动作可达、菜单置换与同步隔离的无模型测试；原文约束可能需要一个新独立后端适配器，不能静默放宽旧数字mask或修改冻结backend。

新配置准入标准可事先固定为原文臂12/12完整物理成功、无输入隔离或输出可达性错误；所有编号臂结果与成败配对均报告。原文臂若不过，不新增例题、请求模板、窗口或重试来补齐这批门槛。若两臂都通过，只说明这批新场景及独立历史设置下操作可行，不能宣称接口修订有增益；若只有原文臂通过，可据新配置的有限证据继续制定局部信息自然语言检查。

**即使新完整信息批次通过，仍不直接解锁符号形成矩阵。** 局部信息下通过真实交流获取事实、采用未来四窗路由的基本操作，以及广播内容对行动的作用仍未验证。新配置门槛与旧v3／CAP门槛分开记录，旧失败不被覆写。这项能力修订不是论文主贡献，只是避免把执行错误归给新符号交流的必要排查。

## 4. 不优先追加旧单例诊断

本次只用标准库环境枚举核对过一个便宜的诊断构造：旧场景1中固定A邀请B从S0送短木材至R、C等待，与固定C邀请B完成相同运输、A等待；B各有唯一满分动作，差别仅搭档。它能检查请求主体改变是否改变B下一动作，但伙伴行为来自研究者脚本，没有自主协商。**不建议本轮执行这张旧单例。** 它即使成功也不能解决完整能力门槛或推进约定形成，不以其低成本替代上述完整检查，更不替代论文证据。

当前交付是一个保留边界的互动候选和一项可被完整能力批次反驳的接口修订。没有执行新训练、推理、符号交流或自动续跑安排。
