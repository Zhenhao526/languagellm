# 单位置检验的数据准备接口

当前只有静态代码和测试，尚未运行正式 `prepare`，没有读取政策消息、实际行动或参数。所有正确动作及属性均来自已冻结环境与旧 transfer 数据的静态真值。

## 发现与验证

发现集使用旧 `train` 的全部 1,944 个内容案例及每案例 18 布局×6 归属，共 209,952 无向案例背景行。端点索引保持旧数据顺序。这里“完整”指全部训练内容案例，并非把重复出现的端点称为不同世界。

发现权重 `base_within_axis_weight` 每轴和为 1；对于固定政策、发送者 S 和轴 q，先选 S，再把该权重乘 3：两个听者等权，听者层内案例均匀，108 个背景均匀。必须分别计算三个轴的响应率，再做“目标轴减另两轴均值”，不能让目的地案例数较多决定发现评分。此数据阶段不选择符号位置，不限制不同轴选到相同位置。

验证只用 `new_needs_and_layouts`。每轴×六种有序发送者/听者取四个案例，每案例取两个**不同接收布局**的布局×归属背景，每背景取一个两端目标材料均换位的合格供体。归属保持不变，但两个接收背景的归属可以相同。共有 72 个案例、144 无向行、288 方向行；三轴各 48 行，各轴/S-L 层各 8 行。没有按政策输出筛选，也不因供体自然失败或符号未变化删行。

每轴无向行等权 `1/48`，每方向 `1/96`，三轴 macro 再除以 3。三个发现轴 q 的验证均用同一批被操纵轴 r 的行与权重。具体候选位置、全部八位置两臂枚举及静默引用由执行方案决定；本数据不把旧草案的 18,432 行当成本轮冻结预算。

## 三个独立排序

统一编码为 `SHA256(salt + '|' + compact_JSON(payload))`，UTF-8，JSON 不含空格；先按哈希十六进制字符串，再按实际语义数组字典序决胜。没有世界 ID、消息、动作或模型成绩参与哈希。

| 层次 | salt | payload |
|---|---|---|
| 层内案例 | `triadic_position_reuse_case_v1` | `[axis_index,S,L,needs0,needs1]` |
| 案例内背景 | `triadic_position_reuse_background_v1` | `[case_identity,recipient_layout,owner_assignment]` |
| 背景内供体 | `triadic_position_reuse_donor_v1` | `[case_identity,recipient_layout,owner_assignment,donor_layout]` |

案例取层内前四。背景遍历全部 36 项，先取排名第一项，再取排名最靠前且接收布局不同的一项。供体只在旧 `eligible` 集中排名并取首项，最多五个候选；旧 donor shift 索引同时保存。不同案例的排序彼此独立；供体资格完全沿用先前已冻结的两端目标材料换位条件。

验证所选 144 行涉及 140 个独特需求三元组、10 个留出需求轨道。其需求三元组和轨道与训练来源 3,888 个需求、49 个轨道不交，布局也与训练 18 布局不交。验证六个接收布局计数为 `27,27,23,25,19,23`；供体布局计数为 `22,21,15,32,18,36`；六种归属计数为 `19,20,25,23,26,31`。这些是固定的平衡案例样本，不是全部背景均匀枚举。个体 24 种需求仍在训练/留出均出现。这里隔离的是位置发现与验证数据，不能把已开发的政策说成全新独立社会。

## 数组接口

`load_sources()` 只读取旧 context 的 prepared/plan/freeze、旧 transfer 静态 manifest/JSON/NPZ，并核对来源哈希。`make_prepared(bundle)` 无 IO，返回：

```
{
  schema,
  discovery: {metadata, arrays},
  validation: {metadata, arrays},
  separation_proof,
  source_sha256
}
```

两个数组集共用：`case_index` 是旧 content 列表序号；`source_all_case_index` 是旧含描述/角色案例的总表序号；`source_spec_row` 是旧 transfer NPZ 行号。`axis/sender/listener/recipient_layout_index/owner_index` 为 `[N]`；`endpoint_indices/target_materials/listener_correct_actions/target_sites/target_destinations` 为 `[N,2]`；`correct_actions` 为 `[N,2,3]`，均是当前接收布局中的真实正确动作。

`truth_attributes[N,2,4]` 的字段顺序为材料种类、长短、目的地、搭档；`truth_field_change_mask[N,4]` 比较两个需求端点。这些字段不以原始地点编号替代材料属性。

验证额外含 `selected_case_index[144]`（本轮选中案例序号 0–71）、`donor_shift_index[144]`、`donor_layout_index[144]`、`donor_endpoint_indices[144,2]`、`donor_correct_actions[144,2,3]`、`donor_listener_correct_actions/donor_target_sites[144,2]`，以及 `eligible_donor_count/view_equal_LL[144]`。端点 0/1 不翻序：same 用当前 b，opposite 用 1−b。验证 NPZ 不重复展开方向。

元数据保存全部发现 content 原案例、全部选中验证案例、三个哈希、完整选中背景和供体记录、原分区 spec、数组 shape/dtype，以及四字段变化计数。真值和选择标签仅供研究者使用，不进入主体观察。

## 检查与准备状态

全发现集四字段变化计数：种类 64,800 行全部 `1000`；长短 64,800 行全部 `0100`；目的地 80,352 行全部 `0010`。验证三轴各 48 行，分别同样三种 mask。其他模式及等待行均为零；没有根据这个检查再筛样。后续可依据两端真值相同的字段构造“未变化要求同时保持”指标。

九项纯测试通过，覆盖独立 SHA 排名、不同布局要求、供体合格性、全部验证行的端点索引和原环境满分计划、材料及搭档、分层权重、轨道/布局隔离、四字段 mask、输入不变及拒绝覆写。测试没有执行正式准备或神经网络。

根任务审阅后才可调用 `python -m research_program.triadic_position_reuse_study.dataset prepare --out …`。准备输出 discovery/validation 各 JSON+NPZ、分离证明 JSON 和 manifest；已有目录拒绝覆写，失败保留收据，不自动重试。
