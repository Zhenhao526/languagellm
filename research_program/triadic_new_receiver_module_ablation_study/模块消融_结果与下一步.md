# 新接收者模块消融：结果报告

## 研究问题

上一轮发现，随机初始化的新 C 在 live 通道下比 silent 通道更容易完成任务，但 Q 增益主要来自物理互选，尚未证明旧协议已经传给新主体。本轮进一步问：这个 live 增益需要新主体调整自己的行动策略、调整发送消息的策略，还是必须同时调整两者？

## 设计

本实验复用已经审计的冻结搭档—新接收者任务：

- A、B 从源实验的最终 live 检查点载入并完全冻结；C 删除后重新初始化。
- 源种子 66701–66708，static/rematched 两个 schedule。
- action-only 只更新 C-action；sender-only 只更新 C-sender1 和 C-sender2。
- full 是上一轮同一批种子、同一源检查点、同一 C 初始化和同一随机流的完整 C 适应参考。
- 每个选择性臂仍比较 live 与 silent，二者共享世界、批索引、消息均匀数和重排分配。
- 每个运行 6,000 步；固定监控集 18,720 个世界，最终新布局集 56,160 个世界。

所有策略仍是本地 NumPy float64 tanh MLP。没有调用 LLM、预训练语言模型、视觉模型或外部网络服务。A/B 和所有非允许模块每步使用精确零梯度。

## 主要结果

最终新布局团队 Q 的 live−silent 差异：

| 适应臂 | static | rematched | 两 schedule 在种子内平均 |
|---|---:|---:|---:|
| full | +22.12 pp [16.82, 27.42] | +19.08 pp [11.05, 27.10] | **+20.60 pp [14.55, 26.65]** |
| action-only | +14.99 pp [7.65, 22.32] | +12.17 pp [6.07, 18.26] | **+13.58 pp [7.14, 20.01]** |
| sender-only | +3.64 pp [−5.32, 12.59] | +2.58 pp [−5.99, 11.16] | **+3.11 pp [−5.55, 11.77]** |

方括号为 8 个源种子的 95% Student-t 区间（df=7）。full 相对于 action-only 的总体 Q 差为 **+7.02 pp**（95% CI [+3.88,+10.17]），full 相对于 sender-only 为 **+17.49 pp**（[+10.63,+24.35]）。对应的中心化监控 Q 时间 AUC 差分别为 **+8.09 pp** 和 **+17.90 pp**。

这说明：

1. 只训练 action 已经能获得大部分 live 优势，说明新主体的行动头是主要恢复瓶颈；
2. 只训练 sender 的 live−silent 差异接近零，单独改变消息生成不能让随机 C 稳定完成任务；
3. full 比 action-only 仍有稳定增益，发送策略的适应提供了额外贡献，但它不能替代行动头适应。

在总体 seed 内平均的最终 live−silent 次量中，full/action-only/sender-only 的物理执行率差分别为 **+54.48/+48.70/+5.77 pp**；proposal 合法率差为 **+12.63/+6.33/+5.05 pp**。目标搭档合法率差分别为 **−13.56/−14.45/−3.05 pp**，说明 Q 增益仍主要来自形成可执行互选，而不是执行后选择了正确搭档。sender-only 的 engagement 率还下降 3.69 pp，进一步说明仅改变发送端无法修复随机行动接口。

绝对性能也支持这一解释：full、action-only、sender-only 的最终 live Q 平均分别为 **33.42%、26.39%、7.90%**；silent Q 分别为 **11.30%、11.41%、4.26%**。三种适应臂都低于旧 C 源策略的 live Q（约 45%），所以本轮仍没有达到“旧协议被新主体完整恢复”。

## 解释边界

本轮提供了比单一 live/silent 对照更强的机制定位：在当前任务和离散通道中，新主体需要先学会把观察转换成自己的行动；发送端的适应会进一步改善与冻结 A/B 的执行配合。它没有证明 C 学会了某个词、组合规则或可独立解释的语义。消息仍是固定长度的 8 类 token，奖励和行动接口都由实验者给定。

sender-only 的近零结果也不能单独推出“发送消息没有内容”；它只说明在随机行动头保持不变时，发送端适应无法克服当前任务中的执行瓶颈。下一步需要固定旧 sender、只训练 action 的消息解码对照，以及新需求组合上的行为测试。

## 下一步实验

下一轮应在同一冻结搭档上做“协议恢复”而不是马上增加任务复杂度：

1. 在 action-only 中加入固定旧 C sender、随机 sender 和可学习 sender-map 三个对照，区分新 C 是直接从奖励学行动，还是利用旧主体的消息结构；
2. 对适应前后策略做未见对象 × 属性 × 目的地组合测试，分别记录行动、物理执行、搭档、地点和目的地；
3. 加入消息重编码和随机 token 对照，检验 action-only 的 live 优势是否依赖旧消息的绝对 token 身份；
4. 若能在新组合上观察到稳定、可重复的消息条件化行动变化，再进行第二代链式传递；每代保留 silent、随机消息和重编码控制。
