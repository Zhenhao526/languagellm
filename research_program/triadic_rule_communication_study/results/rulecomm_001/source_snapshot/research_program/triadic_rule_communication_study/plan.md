# 规则 × 信息 × 通信全因子实验

## 研究问题

本轮检验一个更窄、可因果识别的问题：当第三个主体的提案可以被忽略时，
跨主体消息对“选择哪一组搭档”的作用是否改变？同时比较私有本地信息
（PL）和三人需求全可见（FI），以区分通信带来的信息路由收益与结算规则
带来的执行收益。

## 任务与条件

- 三个主体、四个公开地点、四种材料、六种站点所有者排列。
- 需求集合是 1,560 个三人需求组合；每个世界在每个布局上有且只有两个
  full-success 结构方案，而且两个方案使用不同的搭档对。三种搭档对集合
  AB+AC、AB+BC、AC+BC 各 520 个。
- 观测条件 PL 只给每个主体自己的需求、公共布局和站点所有者；FI 给出
  三个需求以及相同的公共布局。两者使用相同的 54 维官方特征接口。
- 每个主体先输出两次、每次四个位置的八分类无意义符号。live 将符号路由
  给其他主体，silent 保留为发送者私有；消息采样和两条完整轨迹的留一差分
  训练与前一轮保持一致。
- 行动头拆成 neutral/engage 二分类和 16 类地点—目的地—搭档提案。
- strict 规则要求一对主体相互提出同一地点、目的地和搭档，并且第三主体
  选择 neutral；reciprocal 只要求这对主体匹配，第三主体的提案被忽略。

## 全因子与估计量

8 个独立种子（66801–66808）交叉 2 个规则、2 个信息条件、2 个训练日程
（static/rematched）和 2 个通信通道（live/silent），每格 6,000 次更新，
批量 256。每个种子内共享初始参数、世界均匀数、批索引、消息均匀数和重配
排列；所有差异只来自声明的规则、信息、日程或通道及其后续更新。

主要量是六个检查点上物理执行后“实际搭档属于两个合法搭档对”的比例。
对每个种子先计算 live−silent，再计算 reciprocal−strict 的差异，最后在
时间轨迹上做中心化 AUC。次要量包括团队 Q、物理执行率、条件 Q、engage
率、提案合法率、实际执行搭档成员的提案合法率、第三主体 neutral 率、被
忽略和未执行的提案率，以及搭档对和具体方案的选择计数。

## 预注册解释边界

reciprocal 若提升 live 效果，只能说明结算协议改变了任务内通信收益，不能
直接说明出现了词义、公共词典、组合语法或人类语言起源。PL/FI 比较也只
衡量任务所需的信息可见性；本地 NumPy tanh MLP 不是语言模型，也没有外部
模型、教师标签或 API 调用。

## 验证与审计

准备阶段冻结源码、依赖、数据划分、配置和预算。执行阶段保存每次更新的
世界/消息/批索引/重配哈希，每个检查点保存九个网络和 Adam 状态。独立审计
需要从快照逐项重放 128 个训练轨迹、768 个检查点评估和 128 个新布局终点，
逐项比较全部浮点指标、哈希、规则/信息标签和配对流；若预算估算遗漏评估
项，单独写出预算校正记录，不改动数据或训练输出。
