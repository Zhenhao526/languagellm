# 策略优势增益研究：实现架构与审计建议

本文件仅为只读核对及设计建议，尚未选定新种子、冻结执行方案、编写模型或启动实验。所有新增内容限定在 `research_program/policy_gain_study`，不占用 v0.9 命名，也不更改另一个任务的 v0.8。

## 可以复用的实际来源

v0.8 的图像入口由 v0.4 `run_pilot.ImageBank` 提供：读取 `data/manifest.json` 与 `data/features.npz`，只用训练照片拟合中心与统一尺度，载入的是缓存DINO特征。继续使用这条路径可保持旧44／16照片及标准化完全相同，无需构建DINO骨干。

每个种子先用 `make_agents(seed)` 新建两人，再各自进行200×64的个人标量后果准备。初始私人Torch种子为 `seed*1000+who*137`，个人环境与策略随机流分别为 `seed*10000+who*131+7` 和 `+8`。`prepared_{seed}.pt` 保存完整旧ResourceAgent准备状态，但社会 `remake_agents` 只把各自的project深拷贝给新CampAgent；社会接口重新按 `seed*1000+701+who` 初始化，私人投影与identity变换冻结。`make_agents` 会改变全局Torch随机状态，现有 `remake_agents` 明确再次恢复社会接口种子，应完整复用这一顺序。

只读检查27101–27104的全部60份config：每个种子的15条件各自只有一个完整初态SHA、一个可训练初态SHA、一个接收端初态SHA，以及一个prepared来源SHA；prepared实际字节SHA也匹配。可用原 `prepared_*.pt` 和任一原条件 `initial.pt`／checkpoint0000验证旧种子重开的初态。加载社会state_dict仍需先用原构造函数恢复project冻结等requires_grad设置，因为state_dict本身不记录这些标志。

个人完整信息诊断是另外的模型副本：只训练memory、slot_phi与新私人动作头。其最终权重未回灌社会训练。旧种子扩展可引用已通过的4组诊断；新4种子方案应各自重新完成准备和4组诊断，不把诊断训练后的编码器或头当作社会初态。

## 最小实现切口

新增 `train_with_policy_gain` 及研究目录自己的记录层；复用经SHA和模块路径核实的原 `remake_agents`、`training_batch_plan`、`rollout`、`evaluate`、`state_sha`。增益仅进入每个主体、每个角色的策略项：

```text
P = -mean(lp * detach((R - 1) - value))
L(alpha) = alpha * P + 0.5 * MSE(value, R - 1) - beta * mean(entropy)
```

每个人自己的发送、接收角色损失仍等权平均；接收lp仍是两次动作log概率之和，接收entropy也仍求和。两人分别持有参数、计算图和Adam。保持学习率0.0007、总梯度裁剪2、前2100更新熵0.02／后300为0、2400更新×512世界、相同八检查点和五种终点评价。alpha=1使用原组合损失的原样分支，避免人为引入不同计算顺序。

增益放在独立优化配置中，不加入原任务plan，也不加入任何种子公式；新的run_id再映射到原 `split1_additive`／`split1_joint` 等任务配置。不要直接调用原run_experiment或run_controls的main：其默认SEEDS、60组条件、门槛和结果路径属于旧研究。也不要通过改写原模块ROOT或全局CONDITIONS接入新目录。

## 随机流与私人状态如何保持配对

| 路径 | 保持的公式／顺序 |
|---|---|
| 社会更新世界 | `seed*100000+60000000+batch_id+1` |
| 训练地图可达集合 | `seed+47120000+batch_id` |
| 发送抽样 | `world_seed+101+scout*1000` |
| 接收抽样 | `world_seed+102+scout*1000`，两次查询连续消费不同uniform，第二次不重新播种 |
| 检查点评价 | `seed+69100000` |
| 终点评价 | `seed+69200000` |
| 消息干预 | `eval_seed+10001+scout` |

`rollout`先生成一个方向的positions／photo_ids／goals／menu，再生成另一个方向；λ和alpha均不改变外生生成函数或随机流身份。世界哈希按两个方向的这四个字段依次计算。四个实验格在相同种子、划分、更新应有逐行相同的外生哈希；策略动作和后果会随学习改变。发送者不给目标顺序和菜单，接收者的第二查询仍看同一个实际整数消息，不看第一动作或反馈。

每一分支均深拷贝私人参数并新建两份Adam，不能跨分支复用优化器状态；检查所有主体参数指针互不相同、只有自身损失产生自身梯度。保存project和input_transform的初始摘要，并在检查点／终点核对冻结。沿用detached整数消息，不能为记录优势而引入跨主体可微通信。

64组方案的科学描述更完整，适合将2×2交互作为本轮预先确定的主比较；32组方案能较低成本判断当前四个主体对是否对增益敏感。两者都从初态重新训练完整2400更新，不从已有final或中途检查点续训。不新增blocked组时，只能沿用原版本已验证的通道依赖背景，不能声称新增益下的关闭通道对照也已测量。

## alpha=1怎样证明保留原行为

先冻结原模型／任务／数据／依赖版本和新代码；用相同输入张量核对旧损失与新alpha1分支的标量值、全部私人梯度和一次Adam状态／参数更新。再把一个预先指定的、单独计入验证预算的原种子／λ任务从原initial重放到已有检查点，逐更新对照世界哈希、原损失／梯度范数和检查点参数摘要。

上述小量验证证明范围只到实际重放的步数和分支。只有同运行时、同种子、同初值和随机流的全程重放，才能声称整个新alpha1实现逐行为精确重现原运行。若采用旧32增益扩展，原alpha1直接作为冻结旧结果引用，不伪称已重新运行32组。若采用新64，alpha1保持旧算法不意味着应与旧种子的数值成绩相同。

未来验收还应明确：同一初态和第一批抽样下，alpha1/3的原始P、价值项、熵项、动作和R在首次参数更新前相同，只有应用后的策略系数不同；更新后只要求外生世界继续配对。新日志至少保存原P、加权P、价值项、熵及其权重、alpha、裁剪前总梯度范数、是否进入裁剪、参数更新范数和各项实际R/J统计。诊断记录不得反向影响策略随机流或训练调度。

## 可支持与不能单独识别的结论

主比较可固定为每个种子内的 `[J(λ1,alpha3)-J(λ0,alpha3)]-[J(λ1,alpha1)-J(λ0,alpha1)]`，先平均三个划分及方向，保留四个种子的差值；full参照单列。跨λ使用相同J以及同照片N／U和既定协议指标，不用原生R的不同定义代替共同表现。不按中途成败换种子、延长某一格或挑最好检查点。

alpha提高策略项相对价值与熵项的权重，并改变总梯度裁剪，Adam也使其不等于参数步长乘alpha。价值目标及损失系数保持原式，但实际价值预测会随策略后果及共享私人编码器而变化。因此这个2×2检验奖励形状与策略增益的交互，不能单独区分奖励稀疏、探索、信用分配和优化器机制，也不能据此宣称消除了奖励稀疏性。相同初始随机种子不要求两格后续实际行动一致。

所有代码、种子选择、失败处理和验证预算仍待主任务决定；本核对未加载权重或运行任何训练。来源SHA和逐种子初态元数据见同名JSON。
