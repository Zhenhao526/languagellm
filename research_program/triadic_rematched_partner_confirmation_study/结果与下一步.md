# 随机重配搭档确认：结果与下一步

## 研究问题

上一轮完整搭档留出中，训练见过的搭档可以协调，未见搭档在 `all-or-nothing` 条件下保持 0。这里检验一个直接的社会生态改造：仍然排除一个由需求定义的 AB、AC 或 BC 组合，但在 `rematched` 臂把每个训练世界的三份私人需求随机分配给物理主体；`static` 臂保持 canonical 主体分配。若固定物理身份绑定是主要障碍，重配训练应让实时通信在测试的未见物理搭档上产生更强的行为响应。

这轮只保留 `partial + strict`，不再同时改变收益和执行规则。这样主比较只回答“随机重配搭档是否改变通信作用”，把收益生态和 reciprocal 规则留给后续实验。

## 冻结设计

- 16 个新种子 66301–66316，按种子轮换留出 AB、AC、BC，数量为 6/5/5。
- 四个条件：`static_partial_strict_PL_live`、`static_partial_strict_PL_silent`、`rematched_partial_strict_PL_live`、`rematched_partial_strict_PL_silent`，共 64 次训练；每次 6,000 步，batch 256，检查点为 0、100、500、1500、3000、6000。
- 训练需求保留另外两个 canonical 搭档关系，各 1,792 个支持需求；目标搭档的 1,792 个需求只在留出评价出现。每个主体在两部分仍覆盖全部对象、属性和目的地个人需求。
- `static` 使用原始主体分配；`rematched` 对每个训练 batch 世界从六个三人排列中独立均匀采样一个排列，只重排私人需求的物理所有者。公共布局、私有站点所有者、世界随机流和消息随机流不变。
- 评价在 canonical 的未见搭档世界上进行；另在 6 个新布局上测未见搭档和已见搭档控制。消息为两个四元八符号窗口，观察为 PL own-need + public-layout，动作菜单为 17 个，strict 结算要求第三人等待。

主量预先规定为目标搭档两名主体精确行动率的重配×通信差中差：

```text
[(rematched live − rematched silent) − (static live − static silent)]
```

每个种子扣除第 0 步后，按真实检查点间距梯形积分并除以 6,000，最后等权平均 16 个种子。Q、物理执行率和第三人 wait 是次量。完整方案见[实验方案](plan.md)；计划 SHA 为 `cb0c4e126b45c4878c404e897aaf94a7c6c1cbfe42d97baccd3bbbc5abae7241`。

## 为什么主量为负

先看同一训练布局上未见搭档的目标主体率（silent → live）：static 为 **15.3595 → 35.8156%**，rematched 为 **20.6349 → 34.3667%**。因此重配把静默基线抬高约 5.28 个百分点，却把 live 终点略微降低约 1.45 个百分点；通信增益从 static 的约 20.46 pp 降到 rematched 的约 13.73 pp。新布局给出同样方向：static 为 13.9017 → 32.1832%，rematched 为 17.6106 → 32.5822%。

已见搭档新布局控制也没有显示“重配必然更好”：static 为 12.8812 → 14.4196%，rematched 为 11.7465 → 20.3443%。这说明重配会改变策略和基线，而不是单纯增加未见搭档的通信收益。

最窄的解释是：在这个唯一目标行动、strict 等待和固定收益接口中，随机重配促进了无消息条件下的角色／行动先验，因而减少了 live 通道的边际贡献；它没有把消息变成可迁移的关系约定。静默基线的显著上升不能称为语言形成，因为仍然没有对符号形式、公共词典或组合意义的检验。

## 证据边界与混淆

这轮没有得到“随机重配搭档能恢复未见关系的通信泛化”的确认性证据。结果也不能说明随机重配无效于其他任务，因为当前学习器仍有以下约束：

1. 每个世界只有一个原生 full-success 结构计划；主体必须在 17 个动作中命中同一对、同一地点和同一目的地，探索信号很稀疏。
2. strict 规则把第三人 wait 作为合法成功条件，重配改变了 wait／行动的角色分布；wait 负次量提示动作接口参与了主结果。
3. 消息仍是固定槽位的离散包，训练时没有单一发送者的方向可识别干预；即使行为上有差异，也不能排除整包触发或身份先验。

因此本轮测量的是既定通信通道下的社会关系行为迁移，不是词义、组合语法、公共词典、代际传承或人类语言起源。

## 下一步

下一项应直接解除“唯一动作 + strict wait + 稀疏奖励”带来的识别限制，同时保留重配因素：

1. **多合法行动。** 为同一世界提供两个以上可完成的安全计划，并加入显式中性行动；评价使用“任一合法计划成功”、行动集合熵和团队收益，避免把第一个协调事件压成唯一动作命中。
2. **保持关系重配。** 在训练中让同一需求组合与多个物理搭档轮换，测试新配对、新布局和已见配对三类控制；预先分别规定主体行动率和 Q，不能用 Q 单独代表关系抽象。
3. **方向可识别的消息干预。** 只替换一个发送者的首窗，交换接收者或遮蔽某一槽位，测目标主体动作的因果变化；继续保留 silent、随机符号双射和等式模式控制。
4. **再做新主体／代际测试。** 只有当多合法行动下的跨搭档行为和方向性消息效应重复出现，才让新 agent 只看消息和少量行为样本，检验约定能否被传递。
