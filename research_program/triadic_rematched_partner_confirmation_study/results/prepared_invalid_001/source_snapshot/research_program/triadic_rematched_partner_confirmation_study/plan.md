# 随机重配搭档确认实验

## 研究问题

当一个由三人需求定义的搭档组合完全不出现在训练需求中时，随机重配私人需求到物理主体，是否能让实时通信在未见的物理搭档上恢复目标行动？如果只有 `static` 固定主体训练失败，而 `rematched` 训练成功，说明先前的固定搭档结果至少部分来自社会身份绑定；如果两臂都失败，则需要继续修改行动生态或收益信号。

## 冻结条件

- 16 个新种子 66301–66316；按种子轮换留出 AB、AC、BC，数量为 6/5/5。
- 每个种子有四个条件：`static/rematched × partial_strict_PL × live/silent`，共 64 次训练；每次 6,000 次更新，batch 256，检查点 0、100、500、1500、3000、6000。
- 训练需求只保留另外两个 canonical 搭档关系，各 1,792 个支持需求；被留出目标关系为 1,792 个需求。所有主体在两部分仍覆盖全部对象、属性和目的地个人需求。
- `static` 使用 canonical 主体分配；`rematched` 在每个训练 batch 内按六个三人排列均匀随机重配需求，布局、私有站点所有者和消息随机流不变。评价始终使用 canonical 的未见搭档世界，不在测试时重配。
- 观察、17 个动作、两个四元八符号窗口和 strict 结算沿用已审计 D1 接口；不加入加工前置、道路事件或额外信息。

预注册主量为目标搭档主体精确行动率：

```text
[(rematched live − rematched silent) − (static live − static silent)]
```

每个种子先扣第 0 步，按真实检查点间距梯形积分并除以 6,000，最后等权平均 16 个种子。目标搭档 Q、物理执行率、第三名 wait 和新布局控制为次量。重配臂的排列暴露直方图作为机制诊断，不进入主量。

## 解释边界

正主量只能说明随机社会身份暴露改善了当前动作接口下的未见搭档行为响应；它不能证明消息获得了词义、组合性、公共词典、代际传承或人类语言起源。若要讨论语言形成，后续必须加入多合法行动、单发送者接收干预、消息重编码和新主体传递。
