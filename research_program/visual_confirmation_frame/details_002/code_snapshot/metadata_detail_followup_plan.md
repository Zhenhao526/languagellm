# 第二轮文件详情补取固定方案（准备阶段）

2026-09-15。首轮details_001在限流后人工停止，原43份完成回执、failure和离线partial结果完整保留。本轮仅拟补齐其1551个unresolved pageid，不重新请求325个已有完整详情的文件。准备本方案不发出网络请求；须由主任务审核源码、清单和预算后启动。

新源码collect_details_throttled.py，独立新目录details_002。prepare绑定首轮result／records／旧索引、全部原响应与回执SHA、原冻结解析和分组规则及本方案／新源码。按pageid升序每批25个，共最多63批；全部pageid在准备阶段写入plan.json。仍只获取官方Commons imageinfo元数据，字段和初筛规则与首轮一致，原作SHA1及作者字段分组不随结果修改。没有图片、缩略图、模型或编码器调用。

启动须距最后一次已记录429完成时间至少60秒，并晚于所有429的Retry-After截止时间。prepare把这些截止时间逐条保留并计算最迟时间；execute再次检查，不绕过限制。每一请求完成（响应读取和解析结束）之后至少等待5秒才启动下一请求，timeout20秒，串行且每URL在新轮最多一次。理论上限63个请求、每请求20秒socket timeout和最多62次5秒间隔；网络真实耗时不作完成承诺。

**任何429立即保存并停止整个新轮，不继续下一批、不重试当前批。其他网络／HTTP／API／解析错误也立即停止。** 未请求的剩余文件与无有效imageinfo文件继续标为未知，不按拒绝素材统计。每次请求发出前保存URL、pageid、UTC时间；结束后保存原始字节、SHA、HTTP头、状态、耗时和错误，避免再次出现只有进行中context而无请求开始记录。再次执行同目录拒绝覆盖，没有resume。

结果同时保存本轮请求覆盖和合并后的1876条元数据：首轮325份原样沿用，每个新resolved记录注明本轮及新batch。每个初步分组仍最多计1张，但作者字段／链接不是独立摄影者确认，许可模式不是完备许可验收，原文件SHA1不能排除衍生作品和同系列照片。dataframe未完整或未完成来源／像素审核时，不宣称已达到每资源84张。

若全请求结束仍有未知，或再次限流，本轮保留partial和剩余pageid，不自动新建第三轮。后续网络动作由主任务单独决定。首轮冻结源码、请求失败和partial报告均不得覆盖。
