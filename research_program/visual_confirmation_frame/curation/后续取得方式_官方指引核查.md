## 官方当前规则

1. **媒体下载。** Wikitech 的 Robot policy 明确允许原图或标准缩略图，可行时优先缩略图；媒体总并发最多 2，下载速度限制为按 10 秒窗口衡量的 25 Mbps。应遵守 429 的 Retry-After；限制不能当作每个域名各自重置的额度。串行请求加 5 秒间隔并不构成永远不会遇到 429 的保证。[Robot policy，Generally applicable rules／Media API rules](https://wikitech.wikimedia.org/wiki/Robot_policy)。

2. **标准是后端宽度档位。** 当前列表为 `20、40、60、120、250、330、500、960、1280、1920、3840` 像素宽。通过 imageinfo 等 PHP 接口请求的尺寸可能向上取整到标准档；直接构造非标准尺寸的媒体 URL 会被拒绝。这里不是网页显示宽度，也不是“最长边”标准。512 和 768 都不在该表中。[Common thumbnail sizes，含 GHai 对应 FAQ](https://www.mediawiki.org/wiki/Common_thumbnail_sizes)。本次读到该页修订号 `8531221`，最后修改日期为 2026-07-28。

3. **使用 API 返回的媒体地址。** `imageinfo` 可返回文件版本时间、原文件 SHA1、大小、MIME；`iiprop=url` 配合 `iiurlwidth` 返回缩放图地址，另有 `thumbmime` 等字段。请求缩放图时每次最多返回 50 张；`extmetadata` 被列为较昂贵字段，已经存档的作者和许可元数据无需无目的重取。[API:Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo)。这只是文档功能核对，本轮没有对 232 个候选发出该查询。

4. **API 行为。** 文档建议串行、批量查询、缓存可复用响应，并为非交互任务设置 `maxlag`。客户端应如实标识且可联系，不应伪装浏览器。通用 API 建议与媒体 CDN 规则适用范围不同，不能用其中一句“串行较安全”覆盖实际 429。[API:Etiquette](https://www.mediawiki.org/wiki/API:Etiquette)。

5. **不得绕限流。** 基金会政策要求服从减少／延迟请求的响应，不允许通过多个 User-Agent 隐藏同一操作者的使用量；具体端点额度可能变化。本项目不把更换 UA、出口、域名或下载器当成解决当前限制的方法。[Wikimedia Foundation API Usage Guidelines](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_API_Usage_Guidelines)。

6. **工具名单不是下载许可或额度保证。** Commons 页面列出若干批量下载工具；这些工具的存在不保证固定队列可下载完，也不解除上述限流或我们的归档要求。本轮没有安装、调用或访问其外部代码库。[Commons:Download tools](https://commons.wikimedia.org/wiki/Commons:Download_tools)。

## 研究可复现性的区别

下表是对本实验材料管线的判断，不是 Wikimedia 对科学实验的保证。

| 要求 | 归档原图 | 归档官方标准缩略图 |
|---|---|---|
| 文件身份 | 下载字节 SHA1 可直接匹配冻结的原文件 SHA1 | 原 SHA1 只绑定来源元数据；必须另算缩略图自身 SHA256，不能与原 SHA1 比较 |
| 像素处理 | 可冻结本地解码、EXIF 定向、颜色与缩放流程 | 已经过服务端处理；再本地缩放不能恢复原图细节或消除此前处理差异 |
| 以后重现输入 | 使用已归档原文件与冻结本地处理代码 | 使用已归档缩略图字节与冻结本地处理代码；仅存 URL 和请求宽度不保证以后字节相同 |
| 元数据证据 | 原文件可包含格式／EXIF 等；仍需来源与许可审查 | 某些原文件信息可能不在派生文件中，应保留原官方元数据，不能据缩略图补造摄影者证据 |
| 技术纳排 | 原文件短边、单帧和格式可直接检验 | 需分别记录原元数据尺寸与实际派生图尺寸；服务端改格式或尺寸不足须依预定规则处理 |
| 模型输入 | 最终实际输入仍应独立存档／校验 | 同样需要最终输入哈希；不能只报原图来源哈希而不记录派生版本 |

官方 API 返回原 SHA1、版本时间与缩略图地址，可以建立来源对应的元数据链；在没有取得原图的情况下，不能宣称已独立从原图逐像素重算并验证服务端派生过程。严格的“原字节归档”要求若不可放弃，应保留当前未完成状态，待另行确定符合官方规则的原图取得安排。若科学问题允许使用统一的官方派生图，则可将其明确登记为材料管线新版。

## 可以保留什么，必须另行冻结什么

**候选框可以保留。** 不重选类别、来源、作者、pageid、原版本 SHA1、全局分量、确定性排序盐、232 张提名和主备名次；继续执行一个全局来源最多一张、旧来源整分量排除、water 优先以及验收后 48／12／24 分配。换取得格式不应产生第二次按内容挑选来源的机会。原排序在像素前冻结的事实可保留；若之后已有评审看过任何图片，新取得方案的制定时间与知情范围必须另记，不能把后定方案倒写成原先预注册。

新方案至少要在下一媒体请求前固定：

- **像素规格：** 请求的标准宽度，是否按已冻结的元数据长宽比选择档位，返回格式／尺寸／单帧检查，以及拒绝上采样、服务端异常或源版本变化的规则。固定 960 宽不保证短边至少 512；宽图可能更矮。应先用元数据判断规格是否满足原技术门槛，不凭某张图不好看再逐级换尺寸。API 请求值、返回描述和本地实际解码尺寸分别保存。
- **版本对应：** 用固定 pageid 查询的 API 参数与响应原文，核对原版本 timestamp、SHA1、题名及来源；发现更新不能默认改用新版。保存返回的具体缩略图 URL、MIME、请求和响应时间、HTTP 状态、响应头、字节数及缩略图 SHA256。缓存重用也须核对哈希。
- **一致处理：** 所有将进入同一分析的材料采用同一事先确定的处理规则。已取得的 10 个原文件继续留档，但不能因取得顺序方便，前 10 张用本地原图缩放、后面用服务端缩略图，却声称输入管线一致。若保留混合管线，须明确登记该差异，不能假定其无影响。
- **本地派生：** 冻结解码库版本、EXIF／方向处理、颜色模式与色彩管理、缩放算法、最长边 768 的盲评预览规则；保存预览与最终模型输入的哈希。官方标准宽度与本地 768 最长边是两个不同环节。缩略图不自动获得对裁切、修补、去字或生成式处理的授权。
- **请求与停止预算：** 元数据 API 和媒体 GET 分开计数；明确新阶段覆盖哪些固定候选、每文件哪一个派生版本、每 URL 一次、总文件／字节和带宽上限、串行节奏、超时、重定向与版本异常处理。阶段预算和跨阶段累计账分别保存，不能通过新建目录把已有 11 次请求及 22402712 响应字节清零。保留本轮所有成功、失败和未请求记录；新阶段不覆盖旧目录。当前 food 取得仍有独立阶段门槛，不能随缩略图改版自动解除。
- **审查冻结：** 新计划、下载／验证／预览代码、测试、候选清单和源元数据文件 SHA256；将旧原图阶段与新派生图阶段分开报告。图像真实性、显著标签、作者／系列和许可资格仍按既定标准验收，不因缩略图较易获取而放宽。

这是需要另行审议的参数清单，没有预先选定一个缩略图尺寸并请求验证，也没有重新分配训练／确认图。
