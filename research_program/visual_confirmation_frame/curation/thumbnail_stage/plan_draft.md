# 标准缩略图取得与离线处理草案

2026-09-15。**待根任务审阅，未冻结为网络执行方案。** 当前另一用户任务仍在进行 Wikimedia 元数据请求，本草案不控制其进程、不修改其文件，也不向 Wikimedia 新增任何请求。只读取本项目已冻结的 232 个候选及完整 1876 条元数据；不读取原图像素、不解码图片、不运行模型。

## 固定建议与数量

建议所有最终材料均使用 **API 返回的官方标准缩略图字节**，再经统一的本地处理；已取得的 10 个原文件只作为另存的历史归档，不用本地缩放它们来替代本批统一的官方缩略图形式。

按每个候选已冻结的元数据宽高 `W,H`，从 `[960,1280,1920,3840]` 中选择最小的 `d`，满足 `d<W` 且 `min(d,floor(H*d/W))≥512`。用整数运算给出保守的高度下界。更小的官方标准档位均低于 512，不可能满足短边门槛。选择不依赖类别典型程度、像素或模型成绩；不能取得该唯一尺寸时不试探第二个尺寸。

`d<W` 比“不升采样”的 `d≤W` 更严格，是本草案为了统一真正缩小的派生形式而提出的明示技术条件，不回写旧原图方案。允许等宽时有 3 个候选恰为原宽 960，API 有可能直接返回原文件地址；本草案事先排除这一边界。其身份为 apple `180497907、163679404`，water `24902320`。不得把等宽版本是否能返回缩略图作为一次额外网络试探。

建议方案中 207 个选 960，2 个 banana 选 1280；没有候选需要 1920 或 3840。23 个技术不适格候选仍完整保留在账本：19 个原宽不足 960、3 个只有等宽档可用、1 个无法在可用标准档上同时满足短边门槛和严格缩小。它们不从原 232 来源框中消失，也不以未提名的其他文件替补。

固定 1280 的优点是后端宽度单一；代价是严格口径下 banana 只剩 28 个，后续没有任何验收损失余量，也会请求一些并不必要的更大图。自适应规则保留更多原定来源，并减小通常所需的数据量；代价是包含两个服务端宽度，不能声称所有材料具有完全相同的采样分辨率。该宽度差异由原长宽比机械决定且需保留，最终本地缩放不能抹去其历史。

209 是**元数据预测可行数**，不是可下载／可解码／可验收数。water 96 个中仍需至少 84 个通过全部验收，只有 12 个技术合格余量。food 各子类仍分别需 28；不可跨子类补额。推荐集合的原主／备标签分别是 apple 24／13、banana 24／12、orange 27／13、water 79／17；不得把它们重写成一份新的无失败“主候选”名单。

## 保留的来源与顺序

保留原 pageid、题名、原文件 SHA1、版本 timestamp、作者／源键、全局分量、匿名 ID、候选哈希、固定顺序和原主／备身份。技术合格者仅在原队列中标记可请求；排除者留下原位置及规则原因。水优先、全局一个来源最多一张、旧来源整分量排除和后续只合并来源分量不拆分的规则继续适用。

不改原 232 名单，不补搜来源，不换同分量另一张照片，不更换排序盐。全部有界池验收锁定后，仍按原顺序逐 food 子类取前 28 个、水取前 84 个通过者，再按原 `partition` 哈希分 16／4／8 与 48／12／24。当前只规划候选处理，不指定任何一张图将属于训练或确认集。

## 两次冻结边界

**A：元数据解析请求。** 根任务确认其他任务的网络使用已协调、等待要求满足，并批准新计划后，才能冻结元数据请求清单及代码。当前状态是 `network_coordination_status=not_cleared`，不能因本草案准备完成而请求。

仅对技术合格候选调用 `imageinfo`，同宽度分批，每批最多 25 个，`iilimit=1` 请求 latest；参数固定为 `canonicaltitle|url|size|sha1|timestamp|mime|thumbmime`、`iiurlwidth=d`、`maxlag=5`。不重取已有 `extmetadata`，不获取页面图片或缩略图试样。按 water／food 两阶段规划，共 10 个 API 请求：water 4 批；food 6 批。food 阶段继续受已有“先验收足 84 个 water”门槛约束，不能先行执行。

逐 pageid 要求返回身份、canonicaltitle、原文件 SHA1、timestamp、宽高、大小和原 MIME 与冻结详情一致。缺失、改名／重定向、版本变化或对应不明的候选标记失败，不查询历史版本、不改用当前新版本。要求存在专门的 `thumburl`，不能为空或等于原文件 URL；必须为官方 API 返回的 HTTPS 媒体地址，主机仅允许 `upload.wikimedia.org` 或 `thumb.wikimedia.org`，不得自行改域名、路径或拼接其他尺寸。

请求宽度不是实际返回尺寸的证明。返回 thumbnail 宽度须为所选 `d`，高度与冻结比例的 floor／ceil 之一相符，短边至少 512 且两边均不超过冻结原宽高；不符就拒绝，不换档。当前完整详情没有独立 EXIF 方向验证，所以该几何预测不是对服务端定向方式的保证。若服务端返回不同方向／比例，按预定几何规则退出，不能按看见的图临时更改解释。

**B：媒体取得。** 元数据解析结束后，保存所有请求参数、原响应、失败、URL、实际返回规格和 SHA256；形成唯一媒体 GET 清单，另由根任务审阅冻结后才能取图。不执行“API 成功就自动下载”的串联流程。每个候选一个版本、一个官方派生 URL、最多一次媒体 GET；不能追随自动重定向或换成原图／其他尺寸。解析阶段的文件级技术拒绝保留原顺序缺口，网络／HTTP／API 错误则结束该整轮。

原 SHA1 只用于验证 API 报告的源版本；派生响应必须独立计算 SHA256。没有原字节时，不能声称从原图逐像素独立验证了服务端派生过程。API 与媒体请求之间也不是一个原子版本快照，应记录各自时间和服务端返回的版本相关头；不能将来源元数据链夸大为对远端派生过程的密码学证明。

## 请求与累计账

固定串行请求，前次完成至下次启动至少 5 秒，单请求连接／读取超时 20 秒；媒体流另外执行有界读取与整轮截止检查。未来实现需在请求前冻结精确定时和测试，不能仅把每次读取的 socket timeout 当作整个操作的总时限。

媒体接收建议采用不超过 1 MiB/s 的持续有效载荷速率与不超过 64 KiB 的突发额度；其 10 秒窗口上界低于官方 25 Mbps。该本地限速不保证远端不会限流，也不能忽略同操作者其他任务的全局流量。客户端标识和真实联系字段须在执行冻结中登记；不伪装浏览器、不轮换 UA／出口以获取不同额度，不控制另一用户任务。

单派生文件维持 16 MiB 上限，媒体跨阶段累计 2 GiB。已执行的 **11 次媒体请求及 22402712 字节**计入旧账；理论最多新增 209 次媒体 GET，合计最多 220 次，不重置原 252 次媒体请求总上限。当前累计字节余额为 2125080936；派生文件真实大小未知，不能将原文件声明大小之和当作派生响应总大小保证。媒体流按单文件上限、累计余额和 Content-Length 的最小值读取；提前 EOF、异常长度或超预算整轮停止，保留所有实际已读字节。API 响应次数／字节另记，不和媒体 220 次混为一个数字。

任何 429、网络／HTTP／API 错误都结束本轮，保存响应头、错误正文、实际字节、未请求队列和停止原因。Retry-After 必须满足；旧 429 的保守等待截止为 2026-09-15 14:15:13 UTC，但到点本身不授权恢复。新错误不自动重试，不能切换阶段、尺寸或域名继续。单个候选的源版本、格式、几何或校验不符按技术失败记录，不从名单外补图。

## 本地技术验证、预览与特征边界

网络取得只产生未经视觉验收的原始派生字节。技术检查须核实际 MIME、完整解码、仅单帧、尺寸、比例及方向；允许的静态格式沿用 JPEG／PNG／TIFF／WEBP，若 API 与实际格式不一致就拒绝。仅使用该派生文件自身的 EXIF 定向信息，不能再次套用未取得的原图方向。解码库与版本、方向与颜色处理策略在下载前冻结，异常不修补挽救。

盲评预览另从合格派生文件生成：整幅、等比例缩到最长边 768，不升采样，固定 Lanczos 算法，不裁剪、锐化、修补、抹字或使用生成式处理；预览用 PNG 保留已解码的颜色／透明信息，不默默新增底色合成。记录派生字节 SHA256、定向后尺寸、变换参数、库版本和预览 SHA256。若格式／颜色模式无法按此规则处理，技术拒绝或在执行前修订方案，不在看图后自由选择转换法。

评审只接收原匿名 ID 和无标签预览路径，不接收来源题名、宽度策略、主备位置、作者或未来用途。像素判定锁定后才进行作者／系列／许可来源核查；图中清水、真实照片和可读标签等仍按旧标准，不以缩略图看不清为通过理由。来源资格不明者不能进入最终材料。任何分量新合并按旧优先顺序保留并递补，不拆分凑数。

仅在全部验收完成并达到配额后分配训练、流程验收、封存确认。预览用于材料资格审核，**不等于对封存确认图做模型评估**。特征提取属于随后独立冻结的建模阶段：训练主体只能读已授权训练集；流程验收集仅用于事先声明的管线检查；确认集不提前提特征、调知觉门槛、选模型或选检查点。当前脚本不导入图像库或模型，也不生成预览／特征。
