# Qwen能力控制：独立执行前核验

2026-09-15T18:42:50.200106+08:00，11项测试通过。实际使用冻结v3后端的 `Backend.decide` 两阶段包装，只把 `infer` 换成记录函数；没有初始化模型、读取权重、调用MLX或训练。测试不是Qwen能力结果。

主验收记录包含12场、108个决定、216次模拟推断调用（108次私有分析、72次公开广播、36次动作）。假后端每场全等待，12场失败仍全部完成。额外的研究者见证夹具确认12/12才通过门槛，首场失败后11场成功仍不通过，但继续完成全部216次调用。所有夹具合计864次纯Python假推断，真实模型调用为0。

两个窗口的全部输入在生成同窗输出前固定。第一窗不见当前消息；第二窗只见第一窗三条；动作阶段见六条公开广播，不见其他人未执行的动作。私有分析只进入本人紧随其后的正式输出，不进伙伴输入或后续历史。三组、每组三人的历史核对了原始观察、本人动作、本人反馈和公开广播，未混入另一组结果、原始研究者状态、见证或种子。

这里本来就是完整信息控制，四地物资和三人需求均合法可见；不能把“无研究者字段泄漏”解释为本控制有分散信息限制。四个预设种子抽取的场景在三组复用，合计12场，不是12个独立语义抽样。

所有菜单保持17项，且替换抽得的需求、布局、观察分工后，菜单及其种子不变。36个菜单种子互异且不与108个决定种子相交。108个决定种子各异；每个决定的分析与正式阶段按旧后端共享同一个种子，216次调用只有108个不同种子。这是已接受的两阶段设定。

源码和准备输入未被测试修改。新任务的通过标志仅作用于本控制，不修改旧v3能力门槛，不自动启动符号实验。真实tokenizer、运行时和模型行为尚未由本假后端测试执行，后续由根代理prepare/execute并核验。
