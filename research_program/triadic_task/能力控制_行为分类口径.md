# 能力控制的行为分类口径

本口径用于新一步完整信息控制。输入仅为每轮完整信息观察、公开广播、最终动作和环境反馈；不读取私有分析，也不重载模型。统计脚本为 [capability_behavior.py](capability_behavior.py)，只在12场全部完成后生成摘要，输出写入CAP结果目录之外。

物理分类按以下顺序互斥计数：

1. 三人运输：超载。
2. 无人运输：全体等待。
3. 仅一人运输：没有可执行的双人匹配。
4. 两人运输但未匹配：分别检查互选伙伴、同位置、同目的地；三个错误字段可以重叠，不把其合计当成失败场数。
5. 两人匹配：再按实际物资和目的地检查两人的需求，区分两人满足、一人满足、无人满足，对应1、0.5、0分。

同时为每位活跃者记录“所选物资是否符合本人需求”和“目的地是否允许”。需求选择正确但物理匹配失败仍是零交付；物理匹配成功也不自动表示需求选择正确。这样可以区分运力、参与人数、匹配字段与需求选择，不需要从生成文字推断内部原因。

广播部分采用保守的表面提取，只在同一条消息明确出现唯一搭档对、唯一位置、唯一目的地和唯一等待者，且没有被识别到的条件、否定或备选措辞时，记录一个完整候选方案。其他消息均保留原文及提及字段，标为未分类；未分类不等于没有方案。

- 同窗出现两个不同完整候选方案，可记录为“检测到竞争方案”；不能把同窗输出当作彼此已经听取后的回应。
- 第二窗记录支持、同意、维持、调整等原文词语，并比较方案是否与本人或他人第一窗相同。文字变化或重复不单独证明哪条消息造成了改变。
- 三条可识别方案相同，只能称表面方案一致，不能直接称共同承诺或真正共识。
- 若本人第二窗明确方案与本人最终动作字段不同，记录原文、对应正式调用号和两种动作。不能据此称动作mask翻转、私有计划反转或某种内部理解失败。

自动提取不追求完整自然语言语义覆盖，全部72条广播仍保留供逐条人工复核。正式动作分类与文本提取分开汇总。脚本不读取`inference.jsonl`；完整提示、私有分析截断、缓存及模板审计由独立流程完成。

运行示例：

```sh
python3 research_program/triadic_task/capability_behavior.py \
  research_program/triadic_task/results/20260915_CAP_01 \
  research_program/triadic_task/analyses/20260915_CAP_01_behavior
```

同一四个语义场景在三个上下文群体复用，12行不能视为12个独立场景样本。本行为报告不判断语言是否形成。
