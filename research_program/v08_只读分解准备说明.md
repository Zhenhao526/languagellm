# v0.8 接收覆盖只读分解：准备口径

2026-09-15。本分析在得知 v0.8 正式训练已进行、并看到运行进度状态之后新增，属于事后诊断；它不是原固定方案的预注册 U 指标。本次准备读取了方案、协议生产器及训练／轨迹源码，没有根据正式中间成绩挑选 λ、种子、方向或地图。原任务继续负责训练及协议生产，本脚本不接管、不重启这些工作。

## 现存导出确实包含什么

`redesign_v0.8/analyze_protocols.py` 为每个方向导出完整49码×两需求的接收表，以及每码每需求全部720菜单的物理动作计数。自然消息在分析内存中按地图、同一照片对、兼容目标轴保存，但 JSON 仅导出每地图的发出／投递消息频数，**不保存 photo_pair→message 的逐例对应**。因而 JSON 足够分类某地图的自然失败是否缺少任何正确完整码，不能恢复逐照片的自然消息／人工拼接联合对照。

兼容 `sender_goal=0/1` 两行不是两次实际发信，也不是本轮的真实查询顺序轴。生产器将发送目标置零，贪心发信后保留两份平衡索引。本脚本要求两轴发出及投递频数、双目标分子相等，并核对生产器记录的逐照片消息不变计数；随后仅计一次。blocked 也检查 **emitted** 频数，避免恒定零投递掩盖隐藏轴差异。

`final_normal.npz` 的一行则是真实一个世界，含同一行 `photo_ids`、唯一 `sent/delivered`、两个 `goals`、两个独立 `menu`、两个 `action/place/successes`。本脚本使用原世界两次动作共同成功重新计算既定终点 J，并将同一行消息、两个物理动作与完整接收表逐一核对。协议16验证照片对的 N 与正常终点随机照片抽样的 J 分开列出，不逐照片相减。

## 固定读取范围与分母

仅当主 `protocol_analysis.json` 声明 complete、missing 为空，且精确含27101–27104四种子×15固定条件共60运行时执行。每种子条件为三划分×additive/mixed/joint共9，再full三λ及blocked三λ共6。递归目录下的4组个人控制、smoke及partial/full_only协议均不算正式社会运行。

| 范围（每λ） | 地图—方向单元 U | 协议去重 N 的照片情境 | 正常终点 J 的实际世界 |
|---|---:|---:|---:|
| 三划分训练24图，4种子 | 4×3×2×24 = 576 | 576×16 = 9216 | 12×7680 = 92160 |
| 三划分留出6图，4种子 | 4×3×2×6 = 144 | 144×16 = 2304 | 12×1920 = 23040 |
| full全部30图，4种子 | 4×2×30 = 240 | 240×16 = 3840 | 4×9600 = 38400 |
| blocked全部30图，4种子 | 同上 | 同上 | 同上 |

独立重复均为4个主体对种子。程序保留逐地图、逐方向、逐种子分子分母；先在种子内平均三划分／两方向，再等权平均种子。失败中 U=0 占比另给合并失败分母的描述和每种子比率；零失败分母记为未定义，不填零。

U 指固定贪心接收函数中存在**同一条完整码**能满足两个目标。另保留五种互斥地图类型：有共同码；两边际都可由某码满足但无共同码；仅食物边际可达；仅水边际可达；两边际皆不可达。两种边际可以对应不同码，不能把它们拼成同码覆盖。

blocked 对照同时保留全49码的反事实覆盖，以及实际通道仅允许 `[0,0]` 的覆盖和失败分类；前者不称为实际可用信道上界。代码频率、双查询数量与重编码次数都不增加独立训练 n。

## 一致性检查与停止条件

读取当前已审阅生产器 SHA；以后若源码／导出结构发生变化，要求重新审阅，不猜字段。核对配置的源哈希、准备／终点实际路径及其字节 SHA（仅哈希，不反序列化权重）。正常终点检查整数身份、每方向世界编号、每资源一次查询、完整菜单、零库存／历史、真实消息投递、物理计分、9600世界均衡格数、照片类别和原 J 整数计数。

真实两查询的菜单独立，而旧协议 `both` 的菜单轴按相同索引展开；只有全部720菜单对每码／需求给出同一物理行动时，两种口径才能无歧义合并。本脚本遇任意方向非等变，**整体停止标准二元 U/N 分析**，不删除异常方向后报告均值，不临时改成按菜单选最优码。若发生这种情况，需单独固定独立菜单下的可达性定义。

若实际正常终点的动作与保存的贪心接收表不一致，程序也停止，避免将不同评估函数拼接为同世界 J/U。没有重跑模型以“修正”结果的分支，没有挑成功子集的回退逻辑。

## 命令与实际执行状态

[v08_receiver_coverage.py](v08_receiver_coverage.py) 已准备，仅使用标准库及 NumPy，不导入 camp、训练器、Torch、MLX 或DINO。它不会生产原协议文件，只读取原任务完成后的结果；终点只重算正常模式，不冒充五模式完整执行审计。

待原协议完整后，在项目根目录执行一次：

```bash
.venv/bin/python research_program/v08_receiver_coverage.py --out research_program/v08_receiver_coverage_001
```

输出新 `v08_receiver_coverage_001.json/.md`，已有文件不覆盖，输出路径限制在 `research_program/v08_*`。准备阶段未执行真实全条件分析；合成数据检验及独立审查另行记录。后续另有形成轨迹任务，本脚本只负责终点，不新增训练或沿途神经推断。

此分解只能限制“已有接收者是否存在可用码”的解释。λ同时改变效用、部分成功回报和学习信号；J提高不自动等于片段组合结构提高，U提高也不单独证明语言约定已经形成。
