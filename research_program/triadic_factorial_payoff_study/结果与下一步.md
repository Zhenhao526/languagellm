# 收益生态与因素语义留出：确认结果与下一步

## 这批实验检验什么

上一批因素组合留出实验在两个端点都未见的对象×属性资源上没有得到正的通信交互。本批保持同一 D1 任务和语义留出，只改变训练收益生态：`partial` 保留原生的 0/.5/1 训练效用，`all_or_nothing` 把半成功的训练效用映射为 0。物理结算、观察权限和研究者侧评价没有改变。

问题是：全有或全无的合作收益，是否会提高通信对未见对象×属性组合的行为响应依赖？这里的“响应”是研究者根据目标搭档和最终行动定义的 Q，不是模型产生的词义分数。

## 冻结设计

- 任务有三名主体。每个主体有私人需求和公共四位置布局，需求包含对象、属性、搭档和目的地；动作空间保留 17 个动作。没有加工前置步骤和道路事件。
- 每次通信为两个窗口、每窗口四个八元符号。PL 条件只给主体自己的需求和公共布局，其他需求块保持隐藏；`live` 投递跨主体消息，`silent` 只关闭跨主体投递。
- 训练从完整支持中排除资源谓词 5（wood-long）和 6（fiber-short），但保留各对象、长度和目的地的边际值以及相反的单因素角。评价分为 `train`、`heldout_resource`、`heldout_layout` 和 `heldout_both`。
- 16 个新初始化 64101–64116 在 `partial/all_or_nothing × strict/reciprocal × live/silent` 八格中成对运行，共 128 次训练；每次 6,000 次更新，在 0、100、500、1500、3000、6000 留档。
- 每个种子内八个条件共享初始参数、世界随机流和消息随机流，通信和静默只差消息是否投递。主统计是在每个种子内先平均 strict/reciprocal，再对 16 个配对初始化取均值；区间是跨种子的近似双侧 Student-t15 区间。

预备方案和输入冻结哈希分别为 `9c3079f6faf237e8d5cb2b63d38499f058e85fc00e8be2ce870a9bfe97c07c27` 与 `34a83ce2f77c709378c7b36e915921d6e55fbcb93403164e89a58ae1770611a2`。原始设计和主量定义见 [`plan.md`](plan.md)。

## 预先规定的主量：两个端点都未见

主量是在 `heldout_resource` 的 `heldout_changed_actor` Q 上计算的收益×通信交互：

```text
[(all_or_nothing live − silent) − (partial live − silent)]
```

每个种子和规则先减去第 0 步，再按六个检查点的真实时间间距做梯形积分并除以 6,000，最后平均规则和种子。

主结果是 **0.0000 个百分点**，近似 t15 区间 **[0.0000, 0.0000]**。128 个条件的目标 Q 轨迹在六个检查点均为 0。这个结果是该 Q 定义下的结构性零响应；它不是词义等价检验，也不构成对所有可能效应的等价性证明。

同一批次的机制性次量是正确执行搭档率的同形交互，时间 AUC 为 **+22.4820 个百分点**，区间 **[+20.3754,+24.5886]**。6000 步目标分区的端点搭档率如下，显示生态压力确实改变了合作协调，但不能把搭档率直接写成语义形成：

| 规则 | 收益 | silent | live |
|---|---:|---:|---:|
| strict | partial | 16.663% | 32.959% |
| reciprocal | partial | 22.488% | 34.264% |
| strict | all-or-nothing | 0.512% | 39.993% |
| reciprocal | all-or-nothing | 8.733% | 49.699% |

因此，主量支持的结论很窄：在“两个端点都没有在训练中出现”的边界上，本批没有观察到收益生态带来的 Q 泛化交互；收益生态却明显提高了通信对搭档选择的依赖。

## 跨分区 probe：区分评价边界效应

两个端点都未见可能是过严的泛化边界。为检查这一点，执行了只读的跨分区 probe：一端使用训练中见过的需求，另一端使用未见的对象×属性需求，保持合法任务布局和搭档关系。该分析是在看到预先规定的主量为零之后才加入，因此属于**探索性后处理**，不能改写为确认性主结果。

更正后的 [`cross_split_probe_003/probe.json`](results/confirm_001/cross_split_probe_003/probe.json) 使用 576 条合法跨分区边、108 个背景和 128 个条件。非空边层是三个改变主体×`{kind,length}`，共六层、每层 96 条；destination 轴没有跨分区边，空层被明确保留为 0 而没有被当作有效观测。该 probe 只读取 256 个已保存 NPZ，模型前向和优化更新均为 0，收据见 [`receipt.json`](results/confirm_001/cross_split_probe_003/receipt.json)。

跨分区 Q 端点交互为 **+25.9319 个百分点**，近似 t15 区间 **[+22.4101,+29.4536]**，16/16 个种子块为正。strict 的规则平均为 +22.9505 个百分点，reciprocal 为 +28.9132 个百分点。正确执行搭档率的探索性次量为 **+14.2646 个百分点**，区间 **[+11.5957,+16.9335]**。

这两个结果共同提示一个边界现象：当一端需求已有训练锚点时，通信可以支持对未见对象×属性组合的行为响应；当两个端点都未见时，当前任务和学习器没有显示这样的响应。跨分区正结果仍不能单独证明词典、组合规则或语言产生，因为它可能来自共享特征、动作结构、固定整包编码或其他任务内捷径。

第一次 probe 构造因错误地要求九个非空轴层而静态失败，保留在 `cross_split_probe_001`；`cross_split_probe_002` 的数值正确但 scope 文本写成“九层”。`_003` 只修正描述后重新做 JSON/NPZ-only 读取，数值不变。三份记录均保留，避免把失败或后验修正隐藏起来。

## 当前证据能支持到哪里

1. **行为协调层面**：全有或全无的收益压力显著提高了 live 相对于 silent 的正确搭档协调，且效应在 16 个新初始化中可重复。
2. **语义边界层面**：预先定义的双端点未见 Q 没有正交互；探索性的 seen→heldout probe 有稳定正交互。这更像“有一个已知锚点时的跨分区行为迁移”，不是无条件的组合泛化。
3. **语言层面**：当前不能称作词义、组合语法、公共词典、代际传承或人类语言起源。消息的长度、符号表、观察权限、行动规则和评价构念都由研究者预设；Q 是研究者侧行为指标，世界级样本也不是独立社会。

## 下一项应如何做成确认实验

不要直接把 `_003` 的正结果当成论文主发现。下一项应在看到本结果后冻结一批新的初始化，并把跨分区边写入主设计：

1. 使用新种子（例如 65101–65116）重复同一八格收益×规则×通信条件，保留双端点 `heldout_resource` Q 作为负边界对照。
2. 预注册 seen→heldout 和 heldout→seen 两个方向，且只纳入六个非空 changed-person×`{kind,length}` 层；将方向作为设计因素，而不是事后挑选正向结果。
3. 在六个训练检查点直接计算跨分区 Q 交互和正确搭档率，主量使用时间 AUC；只保存紧凑的跨分区指标和末点完整数组，避免再产生不必要的重复 NPZ。
4. 将 partner 次量、物理执行率、完整成功率和 Q 分开报告。严格规则下 Q 为零而搭档率仍上升，说明“执行了正确搭档”不能替代双端点语义响应。
5. 若新批次仍只在有训练锚点的一端出现正响应，中心命题应写成“收益生态调节了任务内协调码的跨边界迁移”；只有在新的搭档、新布局、新组合和独立形成群体上都保持行为泛化，才有理由继续测试消息成分复用和约定形成。
