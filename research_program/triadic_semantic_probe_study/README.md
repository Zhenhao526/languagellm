# 单项需求与跨背景消息诊断

本目录检验已有三人协议表达了什么，以及这种作用在六个保存时点怎样变化。沿用对象、长短属性、搭档和目的地任务，不增加加工或道路事件。主体是独立参数的小型可训练网络；本轮没有新增 Qwen 或 DINO 调用。

使用伙伴生态实验的四个配对种子、唯一兼容搭档生态及四种信息／通信条件，共16个既有政策。只做冻结政策评价，不训练、不补种子、不改变消息长度。两窗各四个符号，字母表大小为8；没有预设词义。

主要读数是留出接收布局上，听者面对同一伙伴的两种需求时，是否在两个情境中都选到适切行动。对象、长短、目的地各占三分之一；两端属于同一案例，四个训练初始化才是重复单位。团队实际完成采集另行判分。

远背景干预只替换一个人的出站消息，同需求与反需求供体共用相同远背景。留出身份只限定接收情境：六种留出布局中，五种的供体来自训练布局。这个设计检验指定映射下的整条消息作用，不是未见组合、语法或人类语言起源的确认实验。

`runner.py` 的 `prepare` 在前向前冻结输入，`execute` 拒绝覆盖已有执行目录。正式结果汇总和独立执行审计各自绑定源码 SHA；它们不在主执行源码快照中。不要对当前目录重新启动或恢复执行。
