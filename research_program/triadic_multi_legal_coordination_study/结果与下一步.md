# 多合法行动协调实验：结果与下一步

## 研究问题

前几轮把每个世界压成一个唯一的 full-success 行动，导致“通信是否帮助主体建立共同约定”与“主体是否能命中唯一动作”混在一起。本轮保留对象、属性、搭档和目的地的表达需求，改为筛选出每个世界恰有两个收益相同的 full-success 计划：两个计划使用同一搭档对，但使用不同地点。实验问的是：在存在两个等价安全方案时，实时通信是否提高了三人选择任一合法方案并实际执行的概率？

这是一项多均衡协调实验，不把任一成功方案称作词义、公共词典或语言起源证据。消息仍是有限离散包，任务没有组合语法、代际传递或新词学习的测量。

## 冻结设计

- 新的16个独立种子为66401–66416；每个种子配对运行 `partial_multi_strict_PL_live` 与 `partial_multi_strict_PL_silent`，共32次训练。
- 从原任务需求中筛得1,452个世界需求，每个世界恰有两个 full-success 计划，三种搭档 AB、AC、BC 各484个；两个计划的搭档相同、地点不同。每个主体位置都覆盖全部24个个人需求值。
- 训练使用18个布局和6个私有站点所有者排列；末点另外在6个新布局上评价。训练和评价均保留两个合法计划，strict 物理结算不变。
- 每次训练6,000次更新，batch 256，检查点为0、100、500、1500、3000、6000。主体只观察自己的需求和公共布局；消息为两个窗口、每窗四个八符号；动作菜单17项。
- 主量预先规定为两个合法计划并集上的团队 Q：实际搭档、地点和目的地属于任一 full-success 计划。按每个种子扣除第0步后的真实检查点间距做梯形时间 AUC，再在16个配对初始化上等权平均。目标搭档主体合法行动率、物理执行率和第三人 wait 是次量。

冻结方案与源文件哈希见 [`plan.md`](plan.md)、[`results/confirm_001/plan.json`](results/confirm_001/plan.json) 和 [`results/confirm_001/freeze.json`](results/confirm_001/freeze.json)。

## 执行和审计

正式执行已完成全部32个运行、192个检查点、32个最终结果、32条训练日志和每种子数组快照。执行程序在训练完成后序列化全局结果时遇到 `TypeError: keys must be str, int, float, bool or None, not tuple`；这只是 endpoint 诊断字典的元数据键不能直接写 JSON，发生在所有训练已经结束之后。失败记录保留在 [`execution/failure.json`](results/confirm_001/execution/failure.json)。

随后只把 `metrics.py` 的诊断键转为字符串，用已有的 per-run JSON 和 checkpoint 做 JSON-only 汇总；没有重新调用模型、重放优化器或重训。汇总结果和收据见 [`aggregation_001/results.json`](results/confirm_001/aggregation_001/results.json) 与 [`aggregation_001/receipt.json`](results/confirm_001/aggregation_001/receipt.json)。独立审计逐个重放192个检查点、30,108,672个紧凑评价世界和270,978,048次模块前向，优化器更新为0，配对、轨迹和“每世界恰有两个合法计划”均通过，最大绝对误差为0；见 [`audit_001/verification.json`](results/confirm_001/audit_001/verification.json)。

图表保存在 [`figures_001/`](results/confirm_001/figures_001/)，三幅 PNG 已实际查看，图表收据标为 `passed`。条件检验和编译测试均通过：2个设计测试、源码 `compileall` 和独立审计均无错误。

## 结果

区间是16个配对初始化上的近似 Student-t 95% 区间，单位为百分点。

| 指标 | live−silent 时间 AUC | 95% 区间 | 6000步终点交互 |
|---|---:|---:|---:|
| 团队 Q（任一合法计划） | **+7.2955** | **[+6.9283, +7.6628]** | **+8.2220** [ +7.8905, +8.5534 ] |
| 目标搭档主体合法行动率 | +3.9719 | [+3.4150, +4.5288] | +3.6707 [ +3.2137, +4.1277 ] |
| 物理执行率 | +53.6829 | [+52.5559, +54.8099] | +62.3449 [ +61.4780, +63.2118 ] |
| 第三人 wait | +1.5526 | [−1.0043, +4.1095] | 0.0000 [0.0000, 0.0000] |

团队 Q 的 AUC 和终点交互在16个种子中均为正。训练布局的终点均值（silent → live）为：Q **19.5475% → 27.7695%**，目标搭档主体合法行动率 **24.1055% → 27.7762%**，物理执行率 **36.7613% → 99.1062%**。6个新布局的对应值为：Q **15.2080% → 22.4030%**，合法行动率 **18.8379% → 24.8910%**，物理执行率 **41.1970% → 83.4473%**；第三人 wait 两种通信条件均为33.3333%。

Q 是未条件化的团队指标，物理执行率的大幅提升会直接抬高它。为检查“执行后是否真的选对合法方案”，追加了一个只读的后验诊断 `Q | any physical execution`。该诊断没有模型调用或参数更新，结果为 AUC **−20.8369** 个百分点，95% 区间 **[−29.0836, −12.5902]**，16个种子只有2个为正；终点为 **−25.2566** 个百分点，区间 **[−27.0316, −23.4815]**，16个种子均非正。原始诊断见 [`diagnostics_001/results.json`](results/confirm_001/diagnostics_001/results.json)。

## 解释边界

本轮最稳妥的结论是：在两个收益相同的行动方案都合法时，live 通信明显提高了实际执行，但未条件化的 Q 增益主要伴随执行率上升；在已经发生物理执行的样本中，通信条件下的合法方案选择反而下降。因而不能把 +7.2955 个百分点写成“主体形成了两个方案之间的公共符号约定”。

当前仍有三个关键混淆：

1. strict 结算和第三人等待仍然把行动信用压缩到少数角色；通信可能先改变“是否执行”，再影响 Q。
2. 合法计划共享搭档对，地点不同；因此本轮没有检验搭档关系是否可迁移，也没有检验一个消息成分是否稳定对应对象、属性、地点或目的地。
3. 消息是固定槽位的整包离散输入，没有单一发送者的方向可识别干预；整包触发、身份先验和位置绑定仍可解释行为差异。

所以本轮测量的是任务内多均衡协调与执行耦合，不能单独证明词义、组合语法、公共词典、代际传承或人类语言起源。

## 下一步

下一轮沿用多合法计划，但把“达成执行”和“选择哪个合法计划”预先拆成两条结果线：

1. 增加显式中性行动和不执行选项，报告任一合法计划成功、计划选择熵、物理执行率以及 `Q | physical`；把第三人 wait 从成功定义中单独列出。
2. 保留两个合法计划，同时在训练中随机重配私人需求与物理搭档，测试已见搭档、新搭档和新布局三类集合；主分析预注册目标主体行动率，Q 只作团队次量。
3. 引入方向可识别的消息干预：只替换一个发送者的首窗、交换接收者或遮蔽一个槽位，观察另一个主体对对象、属性、搭档和目的地动作的反事实变化；继续保留 silent、随机符号双射和跨组包控制。
4. 当多合法行动下的方向性效应在新的独立种子中重复后，再加入新 agent／代际传递，测试约定是否能在少量行为样本下被重新获得。只有此时才讨论形式—内容映射、组合性和稳定传承。

本轮之后已对32个最终策略完成一个后验的单发送者首窗替换探针：在新布局上，计划概率向供体需求方向的live−silent转移为+3.5153个百分点（16/16种子为正），但搭档转移接近零；该结果支持把下一轮主量写成“执行／计划选择／方向性消息效应”三条线，详见[定向首窗探针结果](../triadic_multi_legal_direction_probe/结果与下一步.md)。

本轮代码、原始运行树、汇总、审计、诊断和图表全部保留；研究目标仍在进行中。
