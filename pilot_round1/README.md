# 第一轮本地实验

研究问题：在已有视觉辨别和反馈学习能力的两名神经智能体中，读取最近四次私人交互经历，是否改变符号协议的形成过程和结果？

本轮是机制与实验流程的先导。任务只包含四类物体和四个消息状态，不用于检验句法，也不能从中推断人类语言的历史起源。

2026年9月14日正式批次已完成，14次运行均达到24,000次互动预算。先读[第一轮实验报告](/Users/xia/Documents/ChatGPT/语言/pilot_round1/第一轮实验报告.md)，完整计数与图表见[分析附录](/Users/xia/Documents/ChatGPT/语言/pilot_round1/results/batch_001/analysis/首轮实验结果报告.md)。

## 已固定的实验

| 项目 | 设置 |
| --- | --- |
| 智能体 | 两个独立参数的小型CNN与策略网络，每个141,926参数 |
| 图像 | 32×32灰度图；圆、方、三角、十字，带位置、大小、旋转和像素扰动 |
| 视觉准备 | 每个agent独立进行32,000次奖励驱动的四选一图像匹配；通信阶段冻结视觉编码器 |
| 通信任务 | 发送者只见目标图；接收者只见四个候选图及消息；逐轮随机交换角色 |
| 消息 | 一个离散编号0–3；0可显示为沉默，总容量仍为四种状态；不设消息成本 |
| H0 | 历史输入始终遮蔽，保留正常权重学习 |
| H1 | 读取最近四次自身完整经历，不含未见目标或他者隐状态 |
| 主任务与固定来源对照 | 种子101、202、303，各运行H0/H1 |
| 无通信对照 | 种子101，H0/H1各一次，消息恒为0 |
| 每次运行 | 24,000次顺序互动，每32次更新；评估边界处提前结束更新块 |
| 学习 | 各自REINFORCE、独立优化器，只有共同0/1回报，没有穿过消息的梯度 |
| 评估 | 每2,000次训练后512次新测试；终点2,048次测试，另1,024次独立参考集 |
| 性能确认 | 连续三个预定评估点准确率≥90%，记录第三点；未达到的运行保留 |
| 运行后端 | 视觉准备用MPS；顺序通信训练用CPU，4线程 |

任务目标逐轮独立、均匀、有放回采样。候选位置独立打乱；同类目标和候选也独立渲染。没有有用消息时，接收者期望正确率为25%。类别编号只供环境计算回报与研究者分析，不传入通信策略。

配对条件从同一视觉准备检查点开始，使用相同环境、角色和策略抽样随机序列。同一群体内两个agent的参数、视觉准备经历和私人历史彼此独立。H0/H1使用相同结构与参数量，但历史通路实际获得的信息和梯度可能不同。

种子0仅用于实现校准和CPU/MPS测速，不计入正式结果。24,000次预算和上述日程在正式种子运行前写入批次配置，没有根据主条件成绩临时延长、删选或重新训练。

固定来源对照由环境提供随机但一致的类别—消息映射，只有接收者学习解码。它校准一般映射学习，不代表自发符号形成，其优化过程与双边学习并不完全相同。

## 环境与运行

本次使用项目根目录下的`.venv`，Python 3.12与依赖版本见`requirements.lock.txt`。不下载或调用LLM，也不使用自然语言训练数据。

在项目根目录运行：

```bash
# 重建依赖时使用；已有环境无需重复安装
uv venv --python python3.12 .venv
uv pip install --python .venv/bin/python -r pilot_round1/requirements.lock.txt

# 权限、随机流、梯度与评估检查，不训练模型
.venv/bin/python -m unittest discover -s pilot_round1/tests -v

# 新批次必须使用未存在batch_config.json的目录
.venv/bin/python -m pilot_round1.run_batch --out pilot_round1/results/batch_002

# 本次正式结果分析
.venv/bin/python -m pilot_round1.analyze --results pilot_round1/results/batch_001 --output pilot_round1/results/batch_001/analysis
```

批次在开始时保存配置及实际训练源码的SHA256和副本。框架与设备差异仍可能导致数值轨迹变化；环境元数据可按记录的种子、更新块大小和评估边界精确重放。`batch_002`只是一个新的输出目录；更改科学条件应先修改并另存配置，不能把改参后的运行并入本批。

上述复现命令仍使用101、202、303这三个固定种子，不构成新的独立群体重复。若下一轮需要增加重复，应先明确新的种子集合与研究设置，另存一个实验版本。

## 文件与审查

- `env.py`：纯像素任务与独立随机流。
- `model.py`：视觉编码器、发送/接收策略和私人历史格式。
- `train.py`：视觉准备、奖励学习、冻结评估和符号替换干预。
- `run_batch.py`：在看到主条件结果前固定的14次运行日程与时间上限。
- `analyze.py`：全部重复、学习轨迹、消息映射、干预和历史遮蔽结果。
- `protocol_audit.md`：信息权限、梯度与评估口径的审查记录。
- `verify_replay.py`：按源码快照和实际更新块重放指定运行的外部事件日志，不执行策略训练。
- `illustrate_task.py`：从第一条真实交互重建输入示意图。
- `results/batch_001/batch_config.json`：本批设置、运行环境和源码哈希。
- `results/batch_001/batch_status.json`：完成情况、时间和所有运行摘要。
- 每次运行保存`config.json`、完整`interactions.jsonl`、`progress.json`、`summary.json`和终点权重`final.pt`。起始权重位于批次`pretrained/`。

评估冻结权重和训练末私人历史，不写入新经历，也不反馈结果。历史清空测试同时遮蔽双方历史；它改变输入分布，不能独自证明记忆的因果必要性。终点符号干预在独立参考集上确定自然使用过的符号与含义，然后在新测试集的同一批合格试次上比较原消息和替换消息。只使用一个符号的方向无法进行该干预，指标记为不可估。

每个方向分别记录消息映射。A说B听与B说A听都能成功，并不保证两者共用同一套词汇。仅保存起点、终点权重及中间评估统计；不能事后对中间训练状态追加权重干预，性能确认时间不等于已验证的符号诞生时间。

资源指标中的`process_peak_rss_bytes`是整个批次进程的CPU驻留内存高水位，含此前阶段，不能解释为某次运行独占内存或完整GPU峰值。视觉准备与通信训练的用时分别保存。

`main_loop_seconds`包含初始与周期评估和日志写入，不能作为纯策略更新用时；`train_seconds`还包含终点及参考集评估，不含随后终点权重写盘。`batch_status.json`的总墙钟时间包括视觉准备、所有正式运行与保存，最适合描述本批实际计算投入。
