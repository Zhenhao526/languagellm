# 流程图片补缺第二批：下载前冻结

本批承接 `pixel_workflow_plan.md` 与第一批 `curation_status_20260916.json`，只补流程图缺口。已有合格流程图为苹果、香蕉、橙子各 1 张及水 2 张。固定从原 144 簇预约中的同层 reserve 队列依原顺序取苹果 3、香蕉 3、橙子 3、水 10，共 19 个不同作者簇；请求顺序按原 cluster_rank 排序。既有 metadata / reservation 不改写，选中者保留原 reserve 身份，同时记录本批用途为 workflow replacement。确认 48 张不下载、不读取像素，不增加元数据框，也不自动替补本批失败或不合格项。

下载前保存 selection_manifest.json、源码与所有输入 SHA256，并复制本批依赖的元数据 / 方案 / 第一批状态快照。第一批已知 101 条旧记录中只有 90 张像素可用，9 条下载失败、2 条许可排除；本批明示只与这 90 张、第一批全部 24 张、第二批已成功下载图互比，不能声称覆盖 101 张旧图或确认集。

只 GET 已存 `original_url`，不拼接缩略图地址、不更换服务器、IP 或入口。串行请求，以前次请求结束为起点间隔至少 10 秒。timeout=60 秒；只允许每条候选最多两次尝试。429 / 503 从大小写无关响应头解析 Retry-After 的非负秒数或 HTTP 日期；缺失时用原方案的 30 秒，非法值停止而不猜测。等待在应等待时间之上再加 1 秒，UTC 和 monotonic 两个期限均达到才重试；UTC 若后退则继续等。记录请求开始 / 结束和等待开始 / 结束的两种时钟、期限、实际间隔。403、401、明确验证或访问拒绝、重定向或第二次 429 / 503 均停止本批；不换入口。其他 5xx 或网络暂时错误最多一次等待至少 5 秒后重试，同时仍满足 10 秒串行间隔。所有非成功响应及读取中途失败的已收原字节都保存，记录完整 / 截断状态；网络无响应时存空字节并明确无响应。原图及失败响应单次读取均最多 50 MiB，达到上限而未能确认 EOF 则列预算失败，不解码为合格图。

使用本机已缓存 NumPy 1.26.4（cp312 arm64），不安装或修改共享环境；Python 3.12.14、Pillow 12.3.0 与原像素算法一致，运行环境写入 freeze。原始字节 SHA1 须匹配已冻结 Commons 版本，原尺寸或 EXIF 校正后尺寸须匹配元数据。实际解码格式须为单帧 JPEG / PNG；MPO 或其他多帧 / MIME 不符文件保留原字节并隔离，不进入匿名评审包。

EXIF 校正、RGB 后最长边 640（LANCZOS，不放大），JPEG quality 95；再从实际保存的 640 派生图采用旧 preprocess 的短边 256 BICUBIC、整数中心 224 裁剪。逐图重算并与旧 encode_images.preprocess 输出逐位比对，不加载模型权重。匿名 full PNG 使用 EXIF 校正原图；匿名 sheet 左为校正全图缩放显示，右为实际 224。pHash / dHash 完全沿用原冻结算法（含 DC 的 8×8 正交 DCT-II、中位数严格 >；9×8 右 > 左；阈值分别 ≤8、≤6），同候选原图 SHA1、处理图 SHA256 完全相同也单独标记。召回只代表待人工核查，不能自动宣称独立来源。

匿名 ID 仍是 SHA256(原盐 + '|pixel-blind|' + candidate_id) 前 12 位，按匿名 ID 排序，每 sheet 至多 4 张。packet 只包含匿名 ID、全图 / 裁剪与 sheet 路径及哈希、固定五项标准，不含来源、层、作者、许可、下载次序、模型成绩或格式隔离名单。收集者掌握映射但不做视觉评审；后续两位 AI 评审分别封存意见再比较，标准不变，不把 AI 称为人类评审。

下载时维护可脱离会话继续运行的本地进程与匿名 live_status.json。长冷却期间不占用同步工具长等待，向主任务只报计数、错误种类和最早重试期限。停止或完成后仅离线生成已有合格格式图的匿名包及 QA，不为补齐数量发送新增请求。最终数据可用性仍需双视觉判断、原作者 / 许可复核、近重复关系处理；本批不运行模型。
