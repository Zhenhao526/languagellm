# 新照片确认：前瞻元数据抽样方案 v1

状态：先固定本方案，随后收集官方元数据；本轮不下载、查看或筛选照片，不提取特征，不读新模型成绩。日期：2026-09-15。目标是冻结现有视觉接口后的新照片迁移准备，不是从头训练图库，也不声称排除 DINO 预训练暴露。

## 固定来源、范围与数量

- 唯一素材平台为 Wikimedia Commons。抽样框来自官方 Action API `list=categorymembers`，以下分类的**直接文件成员，不递归子分类**：食物三层分别为 `Category:Apples`、`Category:Bananas`、`Category:Oranges`；水层为 `Category:Glasses of water` 与 `Category:Water bottles` 的并集。
- 范围为真实照片；食物限苹果、香蕉、橙子，水限透明容器中清晰可辨的水。分类只是抽样框，不能替代后续人眼类别验收。树木、空容器、其他饮料、图画、拼图等按后续固定视觉标准排除。
- 分类成员按 API 的 sortkey 升序翻页，每页最多 500 条；每个根分类最多两页、1,000 文件。触及上限保留 continuation 并标记截断，不声称覆盖完整 Commons。当前分类的成员快照不等于历史时点分类成员。
- 从去重的候选标题按下列固定哈希顺序选择元数据请求：每个食物层最多 160 条，水层最多 320 条。先排除已访问 101 个旧候选的规范标题。元数据请求每批至多 10 文件；该预算上限不随许可命中率或模型结果变化。
- 元数据纳入当前上传版本时间不晚于 `2026-09-14T23:59:59Z` 的文件，JPEG/PNG，宽高均至少 256。版本时间不是拍摄日期；记录 EXIF／作品日期但不凭它推断未被 DINO 见过。
- 后续目标配额：流程验收食物 12、水 12；密封确认食物 24、水 24。食物按苹果／香蕉／橙子分别 4+8 张，水为 12+24 张；总计 72 张。每层预留与正式需求相同数量的备用作者簇。配额未满则报告不足，不增加来源、改盐或挑容易图片补齐。

## 固定排序与旧资料排除

固定盐：`visual_confirmation_v1|2026-09-15|prospective|no_model_scores`。SHA256 输入使用 UTF-8、字符串规范化 NFC，标题去 `File:` 前缀、下划线转空格、折叠连续空白并 casefold。框内抽样排序为 `SHA256(salt + '|frame|' + stratum + '|' + title_key)`；不得更换盐寻找更合意的文件。

排除范围为 `redesign_v0.4/data/candidates_downloaded.json` 的全部 101 条，交叉核对 `candidates.json`、`additional_downloaded.json` 与正式 60 张清单。不是只排除最终入选图片。收集前保存各文件 SHA256 及全部旧标题、原图 SHA1、下载字节 SHA256、处理图 SHA256、作者和来源 URL。

精确排除：规范标题、原图 SHA1、Commons 文件页 ID（若旧缓存可恢复）和原作来源 ID 任一命中旧候选即排除。作者采用 Artist／Creator 中的 Commons 用户或 Creator 链接、Flickr 作者链接等原作者身份；上传者不替代原作者。原始 HTML、规范化文本及链接均保存。未知作者、未解析模板和不确定身份先列未决，不分配确认图。

作者相同、同源原作 ID、明确拍摄系列、crop/derivative 关系或近重复关系构成连通簇；关联跨类别也有效。旧作者身份或旧拍摄系列命中的新记录不纳入本 v1，以减少同作者／同次拍摄泄漏。仅靠作者字符串无法解决所有别名；本轮保存可核查候选身份，最终身份消歧未完成的记录保持未决。

**近重复排除尚需像素，元数据阶段不能宣布通过。** 后续若获准下载，覆盖全部旧 101 图及全部新候选，按预先固定的 64 位 pHash 汉明距离≤8 或 64 位 dHash≤6 标出疑似对（应用同样 EXIF 校正与灰度流程）；阈值仅作候选召回，还须检查裁剪、旋转、连拍和同物体不同角度。两名评审确定原作／系列簇，争议由第三次独立判断或保守排除处理。算法实现版本和像素哈希在下载前另锁定，不能按模型效果调整。

## 许可链

只将明确 `CC0`、`CC BY 2.0/2.5/3.0/4.0`、`CC BY-SA 2.0/2.5/3.0/4.0` 且有匹配 Creative Commons 版本 URL 的记录列为元数据许可可用。多许可仅在至少一条可分离的允许许可可核实后采用该条。没有具体依据的 Public domain、GFDL-only、NC/ND、空许可、待删除／版权争议模板先不纳入。

每条保留标题、Commons 源页面、page ID、文件版本 SHA1／时间／URL、尺寸／MIME、原作者原始 HTML 与规范身份、credit、许可短名／URL、署名要求、页面 revision ID（能取得时）、原始 API 响应文件及 SHA256。页面许可记录与 API 快照构成元数据证据链；不把布尔许可标记当作已完成法律核验。正式数据包仍须逐项复核署名与修改说明，图像不能自动归入项目代码许可。

## API 执行、故障与替代

使用说明用途的 User-Agent；串行请求，正常请求间隔至少 1 秒。HTTP 429/503 遵从 Retry-After，若未给则等待 30 秒，最多一次重试；403、验证页或访问限制不绕过。网络超时／5xx 最多一次间隔 5 秒重试。原响应字节、请求 URL、UTC 时间、HTTP 状态、响应头和错误均归档。

若 Commons 分类 API 暂不可用，可通过同一官方 Commons 分类 HTML 页面提取已公开的文件链接与分页链接；它是较弱的分类快照，单独标来源，不合并成 API 成功。文件元数据允许使用官方英文 Wikipedia `prop=imageinfo` 对 Commons 共享文件的公开仓库查询，必须验证 `imagerepository=shared`、Commons description URL 和原 SHA1。此入口本身记录为官方共享仓库后备，不改页面身份。若平台明确要求停止或拒绝该访问，则停止，不用其他入口规避。无官方入口成功时交付失败日志和空／部分抽样框，不伪造可用清单。

本轮无需图片或缩略图，API 不请求 `iiurlwidth`，也不访问图像 URL。元数据页面中的图像 URL 仅保存为来源字段。

## 分组、验收与密封隔离

元数据完成后，以规范作者和系列身份建立临时簇。稳定簇 ID 是各关联身份排序后的哈希；排序键为 `SHA256(salt+'|cluster|'+cluster_id)`。同簇最多取一图，按固定全局哈希顺序、层内配额分配流程验收，再分配密封确认，再分配备用；每个集合的作者簇互斥。初步分配只是候选预约，所有记录仍标记 `pixel_review_pending`、`near_duplicate_review_pending`，不是最终可运行数据集。

后续图像验收应使用随机盲 ID、隐藏标题／文件名／集合身份，查看原图和实际 224 裁剪。按固定项目判断真实照片、目标保留、资源可辨、无明显文字／水印捷径、无混合食物或含糊液体。两名独立评审不看模型分数；替补只能使用同层已固定备用顺序。识别难或模型得分低不能作为技术下载失败处理。

本轮只建立元数据框，不把确认候选送入模型。当前目录的“密封”只是流程隔离标记，不声称具备权限隔离：所有代理共用工作区。真正确认前须另行固定检查点、条件、指标、世界表、阈值和一次揭盲程序，并指定数据保管者。开发者只使用流程验收图；确认图不参与预处理、预算或条件调整。冻结接口的新图测试沿用旧训练归一化，不能在新确认图重算中心和尺度。

## 交付标准

本次必须交付已执行的元数据请求及原响应、去重候选 manifest、逐项排除／未决理由、作者组与临时预约状态、配额缺口和复现命令。成功仅指元数据框可复核，不代表 72 张图像已验收、许可已逐图人工审定、确认实验已运行或获得好结果。
