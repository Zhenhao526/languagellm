# v2 水场景：固定的元数据可行性研究

版本日期：2026-09-16。本计划先于本目录首次网络请求固定，随后与采集源码、配置、旧排除输入的 SHA256 一并封存。只研究官方来源框及元数据可行性，不请求原图/缩略图，不读模型分数，不分配最终像素确认集，也不改动 v1 任意文件。

## 问题与解释范围

检查 Commons 是否存在可追溯的“普通透明饮水杯中可见水”摄影来源类别或描述检索入口，以及在排除旧 101、已下载 60 和 v1 原 144 预约作者/原作关联簇后，本次有界元数据样本能剩多少暂合格身份簇。分类和文字可支持场景候选，不能确认液体、透明度、真实摄影、裁剪保留或作品权属；80 个暂合格簇只是此前的方案候选门槛，不保证达到，也不等于 80 个独立摄影作者。

## 固定网络范围与预算

唯一请求端点为 `https://commons.wikimedia.org/w/api.php`，GET、公开只读。禁止其他 API、网页、原图、缩略图、代理或登录；服务器重定向不自动跟随。允许在 API 内按公开页面重定向解析分类标题，不轮换入口。

最多 **42 次逻辑请求 + 3 次全局额外重试 = 45 次实际 HTTP 请求**，每个逻辑请求至多额外重试 1 次；不因结果不足提高预算。详情如下：

| 步骤 | 固定规则 | 逻辑请求上限 |
|---|---|---:|
| 精确分类存在性 | 一次查询配置中的 6 个精确分类标题及 categoryinfo；记录缺失/重定向 | 1 |
| 分类名检索 | 4 个固定检索式，namespace 14，每式最多 20 结果、不翻页 | 4 |
| 分类直接文件 | 只取名称同时符合水与玻璃杯规则的分类，最多 8 类；精确存在类别先按固定盐排序，再补检索类别；每类最多 2 页，每页 200 个直接文件，不递归子分类 | 16 |
| 文件描述检索 | 6 个固定式，namespace 6，每式最多 50 结果、不翻页；保留各原始检索响应 | 6 |
| 文件详情 | 去重和精确旧标题/page ID 排除后，用固定盐排序，最多 300 个文件；每批最多 20 个 page ID | 15 |

每个范围上限只用于该步骤，未使用请求不转给新查询、更多翻页或更多文件。原抽样框最多 8×2×200+6×50=3,500 条文件引用，实际唯一文件数另记；最多取得 300 个文件的许可/作者/来源详情。即使先出现 80 个暂合格簇也完成已固定详情名单，不按结果提前截断。

具体分类标题、检索式、排序盐、场景文字规则和排除词在同目录 `config.json`，随源码一起冻结。它们限定检索范围，结果不是普通透明水杯的机器视觉标签。类别总计数、API 截断和缺失分别报告；搜索结果中未进入分类规则的标题也留原响应，不临时扩展。

## 节流、失败与停止

串行请求，距上次响应/失败结束至少 10 秒；连接/读取 timeout 60 秒，每响应最多 8 MiB。逐请求记录 URL、参数、UTC/monotonic 起止、状态码、原响应字节、响应头原大小写、SHA256 和异常。响应被截断不当成功解析。

HTTP 403 或明确访问拒绝立即停止，不改身份或入口。429、503、瞬时网络错误或 API maxlag 可在同一 URL 最多重试一次，并受全局 3 次额外重试上限约束。Retry-After 不区分大小写，支持秒数或 HTTP 日期；等待服务端要求再加 1 秒安全余量，UTC 与 monotonic 都达期限才发后续请求。无有效 Retry-After 的 429 等 601 秒，其余允许重试的瞬时错误等 31 秒。等待写入 live 状态，进程持续持有，不因工具超时重启。相同请求重试仍失败、其他 HTTP/API 错误或预算用尽，保存部分结果并停止，不自动另开下一批。

## 元数据排除、分组与记账

1. 冻结读取 v1 旧 101 排除表、全部 800 条元数据、作者关联簇、144 预约及三批已下载清单/状态，连同旧作者重定向补记。旧库全部标题、page ID（可得时）、原 SHA1、作者和原作键继续排除。v1 预约簇的所有已知成员/身份键均排除；三批 60 图全部在该范围，另独立核验覆盖。旧未明作者、不可得像素及别名 pending 保留，不把解析出重定向当作独立身份证明。
2. Commons 普通链接与红链统一提取用户名；保留纯作者文本、Flickr 原作者/原照片等键。上传账号不自动充当作者。按所有新详情的作者/原作/原 SHA1 连接成簇；任一成员命中旧排除，该整簇排除。检查 v1 全部元数据中的关联关系，将旧/预约的排除传播到已记录关联簇。未知作者、身份键不足或明确复合作者暂不算身份可用。
3. 许可采用 v1 精确白名单，不添加新许可；仅 JPEG/PNG、短边至少 256、无归档版权争议信息且有原图 SHA1 的记录进入一般技术/许可暂合格层。所有字段缺失或排除理由逐项保存，不通过分类推断许可。
4. 场景文字需含固定水杯短语（标题/描述）或来自明确水玻璃杯分类；同时排除固定的瓶、喷泉、其他饮料、混合餐食、具名艺术/插画/合成等显式文字线索。泛“drinking glasses”分类不单独成立。自动词表为本框检索可行性的保守规则，可能误排/漏排；没有文字排除不证明纯水或真实摄影。分别报告类别关联、场景文字支持、技术许可支持和身份排除结果，不只报一个“通过”。
5. 同簇代表取固定盐哈希最小文件，再按簇哈希排序；此处只产生后续人工元数据审查顺序，不执行 20/40/10/10 像素预约，不读取像素。若 80 簇不足，记录本次固定有界检索中的不足；不能据此证明 Commons 全部来源都不足。

## 产物与下一道门

保存配置、冻结记录、旧输入快照/哈希、全部原响应和失败、检索框、300 上限的固定详情名单、逐文件 manifest、作者分组、状态和只读 QA。结束时再次核验全部已读取 v1 原文件的哈希，输出元数据可行性报告，说明样本/分页限制及不能从分类确认的条件。

不下载任何新像素。若后续要进入视觉流程，须对本报告的来源定义、身份和许可判断独立评审，并另冻结候选清单、像素验收及确认隔离方案后执行；本计划和元数据门槛不构成自动启动许可。
