# v0.34 固定执行方案：伙伴拓扑轮换与跨伙伴迁移

## 研究问题

v0.33 表明，互补观察能让两个 sender 的局部信息在同一训练团队中被接收者合并，但跨团队 token 替换仍然失败。本轮保持互补视图、双资源收益、token 容量和优化预算不变，只操纵训练期的 sender–receiver 拓扑，检验伙伴轮换是否能把配对特定协议推向公共码本。

## 主体与合法观察

- 四个主体继续使用 `[0,1,0,1]` 两种冻结私有视觉接口；不重新拟合私人接口，不做新的 DINO 前向。
- food sender 只看到 food-only 视图，water sender 只看到 water-only 视图；每个 sender 发一个 token，receiver 只读取有序 token 对。
- `single_full` 和 `dual_same_full` 保留为同一批次中的任务结构控制；拓扑操纵只作用于 `dual_complementary`。

## 伙伴拓扑

三个合法的双 sender schedule 都让每个主体恰好担任一次 receiver、一次 food sender 和一次 water sender：

- A：`(0,1,2)、(1,2,3)、(2,3,0)、(3,0,1)`；
- B：`(0,2,3)、(1,3,0)、(2,0,1)、(3,1,2)`；
- C：`(0,3,1)、(1,0,2)、(2,1,3)、(3,2,0)`。

`dual_complementary` 训练在偶数更新使用 A、奇数更新使用 B；固定的 `single_full`、`dual_same_full` 和评估端点使用 A。终点额外保存 B（训练中见过）和 C（训练中从未见过）两套协议。因而可以分别测量 native A、seen-partner B 和 held-out C；训练 fixture 的随机流不包含 partner schedule，三种条件共享世界和 uniform。

## 收益与指标

使用 `R=.25(cF+cW)+.5(cF*cW)`。主描述性指标为互补条件 native A 相对 v0.33 固定拓扑的 seed-level 变化，以及 rotating condition 的 A/B/C 迁移。辅助指标包括训练/目标/留出 J、food/water 单边正确率、同类型消息一致率、同私有类型 sender token 替换和16种跨团队 token 组合的 all-cross J。

预先解释规则：若 B 接近 A 且 C 也保持，说明伙伴轮换带来可迁移协议；若 A/B 提升而 C 下降，说明只学到已见拓扑；若消息一致率上升但 A/B/C grounded J 不升，记录为形式收敛；若跨团队替换仍远低于 within，不能称为公共词典。

## 审计门禁

先通过支持、视图和 dual 自测，再完成40步 smoke、独立 NumPy 统计和边界审计。正式矩阵为4个 seed × 3个面板 × 3个条件 × 2400更新，共36组运行。`rotation_transfer.py` 和 `cross_topology.py` 只读取保存的 endpoint 表，不导入生产指标模块，不做性能筛选。

## 解释边界

伙伴轮换是四人固定人口中的社会拓扑操纵，不等于出生、死亡、迁移或代际文化传递。C schedule 的失败或成功只说明当前受控协议的 partner generalization，不能直接推断人类语言的词汇或语法起源。
