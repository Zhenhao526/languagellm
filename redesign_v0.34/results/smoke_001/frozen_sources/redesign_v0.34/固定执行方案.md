# v0.33 固定执行方案：互补观察下的双发送者通信

## 研究问题

v0.32 显示，同回合联合收益可以提高消息形式的一致率，但不能稳定提高跨伙伴的 grounded 目标传递。本轮只增加一个结构性条件：同一接收者的两个行动由两个不可互换的发送者分别贡献。食物发送者只看到食物视图，水发送者只看到水视图；接收者必须把两个一 token 消息合并后同时恢复食物和水位置。目标是检验信息互补是否比共享收益更直接地迫使消息出现可交换的组成部分。

## 主体与合法观察

- 四个主体使用 `[0,1,0,1]` 两种冻结私有视觉接口；每个通信模块独立初始化，本轮不重新拟合私人接口、不做新的 DINO 前向。
- 所有主体的 full、food-only 和 water-only 视图由同一冻结两帧视觉输入生成。food-only 只保留食物所在槽位及其存在位，water-only 只保留水所在槽位及其存在位；被遮掉的资源在两帧中都不可见。
- 单发送者条件使用一个 full-view sender 发送两个 token。双发送者条件使用两个 sender，各发送一个 token；接收者按 sender 顺序把两个 token 作为一个49码输入解码食物和水位置。

## 条件与团队调度

每个群体更新包含四个 team slot，四个主体各担任一次接收者、一次 food sender 和一次 water sender。团队顺序固定为 `(receiver, food_sender, water_sender)`：`(0,1,2)、(1,2,3)、(2,3,0)、(3,0,1)`。单发送者条件使用对应的 `(receiver,sender)`：`(0,1)、(1,2)、(2,3)、(3,0)`。

| 条件 | 发送者观察 | 每个接收者收到的消息 | 用途 |
|---|---|---|---|
| `single_full` | 一个 sender 看到 full 视图 | 一个 sender 的双 token | 单发送者基线 |
| `dual_same_full` | 两个 sender 都看到 full 视图 | 两个 sender 各一个 token | 双 sender 但无信息互补的控制 |
| `dual_complementary` | food sender 只看到 food-only；water sender 只看到 water-only | 两个互补 sender 各一个 token | 本轮唯一的互补观察操纵 |

三个条件共享来源、坐标面板、世界索引、位置、照片和 uniform 流；条件不进入 fixture 随机种子。

## 收益与优化

令接收者的食物和水动作正确指示量为 `cF,cW`。所有条件使用同一双资源收益 `R=.25(cF+cW)+.5 cF cW`，基线为 `0.5`。双发送者的两个 sender 和 receiver 使用同一个 detached advantage；每个主体的角色损失取本更新中参与角色的平均值，梯度分别裁剪到 `2`。Adam 学习率为 `0.0007`，前2100步熵权重 `0.02`，最后300步为0；通信外参数保持冻结。

## 预定矩阵与指标

- 来源：34101、34102、34103、34104；坐标置换：p1、p2、p3；每个条件2400个群体更新，共36组正式运行。
- 主指标：`dual_complementary` 相对于 `dual_same_full` 的目标12自然 J 差；独立单位为4个来源。
- 关键辅助指标：三条件的目标/训练/留出 J、food/water 单边正确率、完整双 token 一致率、token0/token1 一致率、按 team slot 的目标 J、食物 token 或水 token 的单独交换重组 J，以及 FW/WF 片段重组与199项完整码双射参照。
- 若互补条件的两个 token 可组合，交换其中一个 sender 的 token 后，应只改变对应资源的解码准确率，另一个资源保持稳定；该性质只在预先定义的离线交换中测量，不把交换结果当作在线生成。

## 运行与审计门禁

- 采样命名空间 `33033`。每个 team slot 每步抽取120个基础世界并展开 food/water 两种遮罩，共240行；四个 slot 共960行世界、双条件8个 token实例或单条件4个双 token实例，以及8个资源动作。
- 先通过支持、视图和指标自测；再运行来源99528、p1、40步烟雾批，验证 full view 与继承 v0.28 cache 一致、互补视图遮罩正确、三条件初始状态配对、team inventory 和协议表合法。正式前写入 `preflight_qa.json`，绑定源文件和继承输入哈希。
- 独立分析只读取保存的 sender/receiver 表，不导入生产指标模块；审计重放所有终点 sender 表、receiver 表、互补视图绑定和抽样训练 trace，但不声称重放全部梯度与 Adam 状态。

## 预先解释规则

若 `dual_complementary` 相比 `dual_same_full` 在四个来源中提高目标 J，并且单 token 交换只影响对应资源，则支持“互补观察促进可组合符号”的有限结论。若双发送者只提高完整消息一致率、交换后两个资源一起变化或目标 J 不提高，则记录为形式收敛而非组合语义。若互补条件不如 `single_full`，说明发送者容量或接收者结构仍不足，下一步先增加 token 容量或延迟转发，不同时改变人口和视觉主干。

本轮仍是受控的两资源通信任务；两个 sender 的角色标签、固定四人调度和预先定义的遮罩不能直接等同于人类社会中的分工、词法或语法。
