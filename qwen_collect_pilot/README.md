# Qwen3.5-9B-8bit 三主体采集预实验

> 研究定位修正：下面的四种需求实验仅用于运行与通信流程检查，不能作为语言形成主实验。后续设计以[语言形成研究目标修正](研究目标修正_语言形成.md)为依据；不能仅通过加长消息，把现有任务视作语言起源实验。

新的具体方案见[语言形成实验v0.2：任务与互动协议](语言形成实验_v0.2_任务与互动协议.md)。新版已在独立目录 [qwen_language_v2](../qwen_language_v2/README.md) 实现，采用8种符号、单条最多32符号、每人每动作步总额64符号和4次同步交流；当前进度见[执行记录](../qwen_language_v2/执行记录.md)。本页后续内容保留旧实验实际条件与结果。

在 Apple Silicon Mac 上使用 MLX 运行 `mlx-community/Qwen3.5-9B-8bit`，以三个独立的私有上下文完成一个简化采集任务。模型权重只加载一份，三个主体不共享互动历史，每次推理使用新缓存。三者共用固定权重和分词器，关闭模型的 thinking 模式。这里的学习是固定模型的上下文适应，不是权重训练，也不意味着模型没有既有语言知识。

当前运行命令显式使用 `--private-reasoning`：每次决策先生成最多 256 token 的私有自然语言分析，再输出受限的正式消息或动作。分析温度为 0，只对当前主体本轮可见，不发送给其他主体，也不写入后续互动历史；实验者日志保留该文本用于审计。原生 thinking 模式仍然关闭。C 的正式消息在互动阶段使用温度 0.7，采集者正式动作与全部冻结评估为贪心解码。

本目录是独立实验，不依赖或修改其他实验目录。是否完成部署及实验，以 `model_verification.json` 和具体运行目录中的 `summary.json` 为准；本说明不预设实验结果。

## 任务

- **A：纤维采集者。** 每轮只看到本地 F0、F1 的随机槽位排列，不知道营地需要哪一种。
- **B：燃料采集者。** 每轮只看到本地 G0、G1 的随机槽位排列，不知道营地需要哪一种。
- **C：需求协调者。** 知道所需纤维与燃料的类别，看不到两个采集点的槽位排列。

C 向 A、B 广播同一条 `@#%&` 字母表中的 0–2 字符消息；不预设符号含义或字符位置的含义。每个可用字符均验证为一个独立的单 token，解码时使用 logits 硬屏蔽信道之外的 token，保证消息不会夹带自然语言、空格或隐形字符。A、B 分别输出 `0` 或 `1`，待两人的动作都提交后结算。双方都选对才算群体成功。

A、B 只得到自己的匹配情况和群体成功反馈，C 只得到群体成功反馈。每轮需求与槽位排列独立变化；所有观察为**文字描述的离散资源**，本轮不使用图片。资源概念、三个角色和单向广播结构由实验者给定，本任务不检验内生分工或自由对话。

采集者只有二选一且完整看到两个候选，所以“自己匹配”的事后反馈可以反推出该轮目标资源。这是较强的学习信号，但反馈在动作提交后才提供，不泄漏待决策轮次的目标。

四个二值环境变量构成 16 个等概率状态。在固定历史与无消息的条件下，任意确定性本地策略组合的群体成功率恰好为 **25%**；这可以通过完整枚举验证。随机抽取少量轮次的成功率不必恰好是 25%。

## 本地环境与模型

部署目标是当前的 Apple M5 Max、48GB 统一内存 Mac，使用 Metal 加速。模型文件约 **10.45GB（十进制）**，位于 `models/Qwen3.5-9B-8bit/`。加载后的内存还包括推理缓存和运行时，以日志中的实测值为准。

`model_manifest.json` 记录模型仓库、下载时固定的 commit、每个文件大小以及上游可用的 SHA-256。`verify_model.py` 在运行前逐文件检查；仓库自定义 Python 模型代码不启用。首次部署固定所下载的版本，已经下载并验证后，复现运行直接使用该版本，不需要重新执行下载。

```bash
cd /Users/xia/Documents/ChatGPT/语言/qwen_collect_pilot

# 首次建立独立环境；已有 .venv 时可跳过。
uv venv --python /Users/xia/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 .venv
uv pip install --python .venv/bin/python -r requirements.lock.txt

# 首次下载及校验；重新执行 deploy.py 会复用 manifest 中已固定的 commit。
.venv/bin/python deploy.py
.venv/bin/python verify_model.py

# 运行有实际意义的环境、上下文隔离与解码信道检查。
.venv/bin/python -m pytest -q

# 可选：仅加载模型并执行一次简单输出检查。
.venv/bin/python run_pilot.py --smoke-only

# 当前小规模预实验：显式开启私有分析，两组各 24 轮。
.venv/bin/python run_pilot.py --private-reasoning --rounds 24 --seeds 17 29

# 复现早期直接受限输出方式：省略该 flag（CLI 默认仍是关闭）。
.venv/bin/python run_pilot.py --rounds 24 --seeds 17 29

# 将命令输出的 RESULT_DIR 对应目录代入；不要使用未完成运行冒充完成结果。
.venv/bin/python analyze.py "results/<timestamp>"
```

如果迁移到另一台机器，使用当地 Python 3.12 路径建立虚拟环境，并修改上述 `cd` 路径。`requirements.lock.txt` 固定本次安装版本；模型运行需要支持 Metal 的 Apple Silicon 环境。脚本不启动 HTTP 服务，也不需要向第三方推理 API 发送实验记录。

## 实验流程与对照

1. **已知协议能力对照。** 程序用明确约定的四种消息编码四种需求，检验两名采集者是否能正确解码与选择槽位。当前对照采用独立的简短单 user 提示，只包含角色相关消息映射与当前槽位；C 在这个阶段不调用模型。该对照上下文不会进入自由编码实验；若群体成功低于 15/16，运行器停止，先检查任务执行能力。自由编码阶段使用另一个包含完整任务说明与历史的提示，所以该能力上限检查通过，也不能保证复杂历史中的动作选择无误。
2. **零互动冻结评估。** 三个主体历史为空，C 自行输出消息。枚举全部 16 个状态，同时评估原消息、空消息和跨需求置换消息。这可以观察尚无互动反馈时，共同预训练先验是否已支持某种协调。
3. **两组独立互动。** 默认随机种子为 17、29，各从空白私有历史开始，随机运行 24 轮。C 的温度为 0.7，采集者贪心解码。环境随机数与模型采样种子分开；每轮反馈仅追加到各主体自己的记录。
4. **互动后冻结评估。** 固定各自历史并关闭反馈，再贪心评估全部 16 个状态的三种消息条件。置换将 `(dₐ,dᵦ)` 的消息替换为同一编码者对 `(1−dₐ,1−dᵦ)` 产生的消息，保持消息分布。报告会说明实际改变了多少消息，因为编码碰撞可能使部分置换无效。

冻结评估中完全相同的私有提示词可以复用确定性输出；此复用只在当前冻结评估内生效，不向模型传入其他角色的信息。原消息与置换消息评估不是额外学习轮次。当前轮次编号、全局世界状态、其他主体的私有观察和当前动作都不会加入主体提示词。

互动时 C 的温度为 0.7，冻结评估为 0，因此两者并非同一行为策略。前后比较应使用零互动和互动后的贪心冻结评估；互动随机样本成功率用于描述过程，不与冻结成功率直接相减来估计学习增益。

私有分析自身统一使用温度 0，正式输出再使用上述阶段温度。分析最多生成 256 token，若 `finish_reason=length`，说明达到长度上限，可能尚未完成分析；报告单独统计此类调用数，不能把截断或动作执行错误直接解释为没有形成有效编码。

实验者日志允许包含全局信息，用于审计；模型输入仅由该主体允许看到的观察、消息及自身历史构造。报告区分训练随机样本率与冻结状态枚举率，并记录符号频数、时长及 MLX 峰值内存。

`inference.jsonl` 中 `mode=private_reasoning` 记录分析步骤，`mode=message` 或 `action` 记录正式输出。截断统计只计分析步骤的 `finish_reason=length`。启用此功能后，一次未复用的主体决策通常对应两次推理调用；其他主体始终只收到正式广播的 0–2 个符号。

## 研究解释的限制

这是运行与任务设计的预实验。预训练语言知识、符号偏好、资源标签及提示词都可能影响编码，三个上下文的独立性不等于三个模型具有独立的文化背景。互动后的进步也需要与零互动表现、消息干预及更多随机种子一起判断。

该任务只有四种需求，信道包含空串在内有 21 种消息，一个整体查表协议就足以解决任务。高成功率不能单独证明组合语法或语言起源。本次未设置新概念组合、代际传递、陌生主体迁移或环境超参数扫描；这些应当在运行与任务有效性得到验证后另行设计。
