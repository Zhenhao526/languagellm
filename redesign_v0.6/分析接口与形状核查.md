# v0.6 汇总分析的接口与形状核查

状态：训练设计和接口尚待固定。这份文件只记录分析迁移要求，不把拟议条件当作已执行方案。旧版 `redesign_v0.5/analyze_stages.py` 保持不变。

## 可以复用的逻辑

- 不导入训练器或神经策略，从保存轨迹独立重算采集、需求满足和分组均值；核对 `result.json` 中的记录结果。
- 检查 `config`、`result`、检查点、训练更新连续性、源代码哈希和初始/终点参数来源。
- 以主体对训练种子为重复单位，保留每种子、每方向和每条件结果；报告等权均值及各种子值，不把评估案例数当作训练重复。
- 同起点、同预算、同外生评估序列的配对比较。课程与混排按 `batch_identity` 检查整个训练批次多重集；直接条件若暴露不同，只声称更新预算相同。
- 正常、打乱等模式的每步及总体奖励重算；来源固定时，检查协议探针与实际终点参数的文件哈希一致。
- 终点图保留种子散点和均值；过程图仅连接真实检查点，不从稀疏检查点插值“第一次涌现”。

## 必须移除或参数化的 v0.5 假设

| 旧版假设 | v0.6 要求 |
| --- | --- |
| `permutations(range(4),2)`，固定 12 张地图 | 从冻结配置读取 `n_sites` 与合法有序地图；六地点两种资源不共址时应为 30 张地图。 |
| 固定 `OUT4` 与 `in8/out4` | 每个 `split_id` 保存明确的训练/留出地图列表及哈希。字段使用 `train_maps/heldout_maps`，不把地图数量写进键名。 |
| 只用种子匹配比较 | 比较键至少包含 `(split_id, seed)`；只在该单元内核对世界、预算与起点。不同划分不能强求训练世界相同。 |
| 3 个种子、A/B/C 固定目录和 54 个预期运行 | 从执行方案或独立 manifest 读取预期运行全集；缺失、失败、开发试验单列，不从成功结果反推“全部完成”。 |
| 目标范围 0–1、位置和动作范围 0–3、菜单宽 4 | 两资源可保持，但须配置声明；地点和菜单宽改为 6，并验证动作索引经各自菜单映射后的位置。 |
| 空历史 14 维，事件 7 维 | 若保留两事件历史，六地点对应每事件 `6+2+1=9` 维、总 18 维；若新批仅静态单轮任务，应按真实接口省略历史，不伪造动态验收。 |

| 容量 2、初始库存为零、三步持续段 | 只有新方案明确保留时才核对；不把 v0.5 的环境规则默认为 v0.6 的事实。 |
| 全图无通信 25%、单 5 符号 17/24、持续三步 265/648 | 不复用旧上界。六地点均匀完整地图的静态无通信期望为 1/6；其他分布、容量条件和动态上界须用新独立数学核查结果。 |
| 序列 2×5 与原子 25 选 1、重编码 `range(25)` | 读取 `vocab**length`。完整 30 地图需要足够整体消息容量；2×5 的 25 码不足。若采用 2×6 与 36 选 1，则名义容量匹配为 36；仍须报告架构/参数不同。 |
| 每方向枚举 24 个菜单、9216 跨目标记录、36864 替换记录 | 六地点菜单有 720 排列；分母全部从探针的真实整数计数读取并独立相除，不能复制旧数字。 |
| 两个符号位置对应两种资源的校准 | 若仍为两个消息位置，可以保留两个候选位置分配；必须在校准资料选定，并在验证资料评价。原子消息无局部位替换，标记不适用。 |

## 多个平衡留出划分的汇总

每个划分先核对：训练与留出地图不交叠、并集等于规定合法地图集合、每个资源—地点因子的训练覆盖及其频次。若称“平衡”，须从真实列表核验其具体平衡性质，不能只根据文件名判断。

完整地图评估、训练地图子集和留出地图子集均报告样本数与奖励。相同训练种子在多个划分重复使用时，不能把 `种子数×划分数` 当作全部独立重复。先保留每个划分×种子的结果，再报告每个种子跨划分平均，以及各划分的稳定性。条件差也先在同划分、同种子内相减。最终统计口径由实际初始化关系固定。

若 probe 平衡枚举与随机 episode 终点评估采用不同照片组合、地图权重或菜单数量，分开报告。不得把枚举高分直接替换随机终点评估结果。

## 结构探针的计算量与解释

六地点的菜单排列数从 24 增至 720。跨目标完整枚举按 16 照片组合、30 地图、2 目标、720 菜单计算，每方向有 691,200 条；若不先折叠菜单，局部成分替换枚举还会更大。

可以先验证每条消息、每个需求在全部合法菜单下对应同一实际地点，然后折叠菜单重复；核查应保留整数分母与折叠原因。否则须保留菜单维度，不能因计算量大就把未验等价的菜单删除。跨目标行为、局部替换、整体重编码参考和留出拼接仍分别报告。

重编码的基准须与本次实际消息容量一致，保留自然行为与完整消息的频次。参考分布属于已训练协议的条件重编码比较，不是新训练重复、总体置信区间或语言学创新的显著性检验。

## 训练器接口固定时需要的最少资料

1. 执行 manifest：预期 `(split_id, seed, condition)` 列表，预算、检查点、评估模式、冻结代码与数据哈希。
2. 环境配置：地点数、资源数、合法地图及各划分、消息形状、是否目标可见、动作菜单和额外合法观察的定义。
3. 运行 `config/result/curve`：初始化来源、最终参数指纹、训练世界批次身份和评估案例数。
4. 最小终点 NPZ：方向、episode、地图资源位置、照片 ID、需求、菜单、发送/接收消息、动作/实际地点、奖励。只有环境实际包含库存、历史或动态资源时再要求这些列。
5. 独立数学上界与机制 probe 的结果 schema；报告读取其元数据及整数计数，并校验终点参数来源。

分析脚本只在 `redesign_v0.6/` 新建；最终接口给定后再实现，避免把未确定设计写成既定事实。
