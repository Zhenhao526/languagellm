# v0.6 六地点组合留出实验

核心问题：上一轮有限地图中的符号成分复用，能否扩展到更多地点及未训练的资源组合？相同训练材料的呈现顺序会怎样改变它？

状态：`results/recombination_001`的56个固定预算运行及协议分析已全部完成，四个新主体对种子均保留；完整执行审计56/56通过。

- [六地点组合留出实验报告](results/recombination_001/analysis/六地点组合留出实验报告.md)：全部对照、形成曲线、协议结构、负结果与下一步能力问题。
- [协议与完整码重编码结果](results/recombination_001/protocol_analysis.md)：112个通信方向，88个双符号方向共8,800次前置规定的重编码参照。

新地图上的单目标准确率：课程36.14%、混排37.74%、直接训练45.39%、原子码41.27%；相应训练地图成绩为65.88%、76.91%、79.46%、65.98%。直接训练的留出成绩在四种子中均高于课程和混排；混排相对课程的留出优势并非所有种子一致。全30图通信参照80.35%，始终关通道16.67%。

直接条件在留出地图上，自然消息同时支持两个需求均正确的比例仅4.08%；用训练消息成分人工拼接后为15.40%，各自整体重编码参照为0.47%。全30图严格片段替换为23.36%，重编码参照4.81%。结果支持有限的片段复用，可靠的自主新组合产出仍然不足。人工拼接由实验者根据目标地图选择供体，不是主体自主完成通信，也不能据此唯一确定产出或视觉表征的因果瓶颈。

六地点、食物和水两资源、30种有序地图。三个完美匹配的双向组合各留出6图、训练24图。每种子每划分比较两符号课程、相同批次混排、直接训练及49原子码直接训练；另有全部30图直接训练与始终关通道参照。所有主体均从新的独立个体准备起步，没有继承上一轮最佳协议。

视觉骨干仍是冻结的官方DINOv2 ViT-L/14，照片仍为此前44训练/16开发留出，不能称为新视觉确认。私人需求分支、公共地点坐标和合法动作掩码均是给定接口。该轮单独研究组合规模与训练安排，没有同时添加新资源类型、长期记忆或自由分工。

固定随机地图代码的动作诊断中，两个序列接收者均90%，两个原子码接收者95%与91.67%，达到事先≥90%门槛。初次布尔判定被float32的0.899999976错误触发；已从保存的逐例动作与收益按8640/9600整数计数修正，没有重训或修改门槛。原始判定与实际执行源均保留在诊断目录。该诊断不等于自然通信结果，其代码与权重均未回灌主实验。

## 复现

在项目根目录执行，使用已有PyTorch环境，不需要下载或重新部署模型。已有完整且配置/源代码一致的运行会跳过；部分写入的运行不会被覆盖。独立重跑应指定新的结果目录。

```bash
redesign_v0.3/deployment/.venv/bin/python -m unittest discover -s redesign_v0.6 -p 'test_*.py' -v
redesign_v0.3/deployment/.venv/bin/python redesign_v0.6/run_experiment.py --out redesign_v0.6/results/recombination_001 --seeds 25101 25102 25103 25104 --updates 2400 --batch 512 --eval-n 9600
redesign_v0.3/deployment/.venv/bin/python redesign_v0.6/audit_execution.py
redesign_v0.3/deployment/.venv/bin/python redesign_v0.6/analyze_protocols.py
.venv/bin/python redesign_v0.6/analyze_recombination.py
```

主运行保留准备状态、初始及终点模型、优化器、检查点、每步训练指标、训练地图池、可达集合、输入哈希、执行方案与源代码快照和五模式逐例轨迹。开发用`smoke_001`和`receiver_control_99102`不计入56个主运行。

更换结果目录时，执行审计使用`--root 新目录`，协议分析使用位置参数`新目录`，报告汇总使用`--input 新目录`。协议分析按来源哈希缓存已完成检查，支持断点继续；缓存不训练或改动主体。
